**日期：** 2026-09-21 · **分支：** `v15-interactive-channel-workspace` · **起止 HEAD：** `9d78d1c`（未提交）

**范围：** 只修 Tissue Preview popup 里那一行成功元数据占据点击区域的问题。不处理冷读取性能、cuCIM 来源重绑、G3.2c ROI 裁切或其他任何事。

## 1. 原状态行为什么不能点

`OverviewPanel.status` 是面板布局里的一个真实 `QLabel`（`ui/step0/overview_panel.py:1321`），**不是画布上的透明覆盖**。它按正常方式占据一行布局高度，所以落在那一行上的鼠标事件根本到不了 `gview.viewport()`，`OverviewPanel` 装在 viewport 上的事件过滤器不会运行，`navigate_requested` 也就不会发出。

成功加载后 `_on_overview_loaded()` 往里写的是纯元数据：

```
Full image 59040×42000 px  |  Overview 48×34 px  (0.3s)
```

对 Tissue Preview 的用户来说这行字没有任何可操作信息，却吃掉了一条他们正想点击的组织带。

## 2. popup 局部显示策略

只在 `TissueNavigatorPopup` 里，对**它自己那一个** `OverviewPanel` 实例的 `status` 标签加策略：

- `_is_overview_metadata(text)`：把空白折叠后判断 `以 "Full image " 开头` 且 `含 "| Overview "`。按面板实际写出的那句话匹配，不看颜色、字体，也不新增任何需要同步维护的标志位。
- 命中 → `label.setVisible(False)`；其他任何文本 → `setVisible(True)`。标签保持默认 size policy，所以隐藏时**它的布局高度被释放**，不是留白。
- ~~成功元数据顺手挂到 `gview` 的 tooltip 上，供诊断；不新增任何可见 UI。~~
  **已于 2026-09-22 由 G3.2b.3.2 撤销，见本文 §8c。**「不新增任何可见 UI」这句判断是错的：
  tooltip 就是一层可见 UI —— 真机上鼠标停在 Tissue Preview 任意位置片刻，
  `Full image … | Overview …` 就会浮在用户正要瞄准的画面上。
- 构造时立即应用一次，避免初始状态与后续不一致。

**挂钩方式：** 包装**这一个实例**的 `label.setText`。`QLabel` 没有 text-changed 信号，而父控件的 `LayoutRequest` 只在 size hint 真的变化时才发出，两者都不能可靠地捕捉面板写的每一条消息。`OverviewPanel` 的类、`_on_overview_loaded()`、文本生成逻辑、坐标/鼠标/ROI/patch 语义**一律未改**，`status` 也没有被删除。

## 8b. G3.2b.3.1：真机验收失败后的收口——下面那一行顶了上来

**真机验收失败。** 隐藏成功元数据行之后，它下面的 `_info_lbl` 立刻上移占住那条带。用户看到白字没了，但原位置附近仍然不是画布，点击到不了 `gview.viewport()`。

**我第一轮的门为什么错误地通过：** 它只点了"旧状态行中心"这一个点，并且**没有挂载工具栏和 ROI/Patch 列表**。在那个简化层级里画布确实长高到覆盖了那个点，于是门通过；真实层级里列表占走空间、`_info_lbl` 正好落在画布下方，门却看不见。

**实测（挂载真实形态工具栏 + 列表、Step1 的 `delete_only` + `patch_editable`、真实 ROI/Patch 信息）：**

| | 修复前 | 修复后 |
| --- | --- | --- |
| `status` | 已隐藏（G3.2b.3） | 已隐藏 |
| `_info_lbl` | **可见，`(4, 285, 404, 18)`——文本为空时仍占 18 px** | **隐藏** |
| 画布 viewport 高度 | `261` | **`282`** |
| 画布与列表之间剩下的 | `_info_lbl`（纯文本行） | 只剩面板自己的 **patch 控制行**（22 px 的可见控件）+ 布局间距 |

**画布并没有一直延伸到列表，这是对的：** 中间剩下的是面板自己的 patch 控制行，那是**控件**不是说明文字，删除控件不在本块范围内（UI_SURFACE_RULES）。门断言的是"画布与列表之间不再有任何纯文本行"，而不是"完全没有间隔"。

## 8c. G3.2b.3.2：彻底移除悬停元数据（2026-09-22）

**真机验收结果：** G3.2b.3.1 的**底部点击已通过** —— Tissue Preview 最底部现在可以正常点击空降。
但**同一轮验收发现了本报告 §1 埋下的问题**：鼠标在画布上停留一段时间后仍会弹出
`Full image … | Overview …`。

**准确来源：** `ui/widgets/tissue_navigator_popup.py::_apply_overview_status_policy()` 里的

```python
# Kept where a reader can still find it, without adding any surface.
panel.gview.setToolTip(label.text() if metadata else "")
```

即本报告 §1 所写「顺手挂到 tooltip 上供诊断」。当时的理由是「不新增任何可见 UI」，
**这个判断是错的**：tooltip 是一层会自己浮出来、盖在画面上的 UI，而且它盖住的正是用户要点的组织。
用户明确要求彻底去掉，不是搬走。

**最小改动（只改那两行）：** 无条件清空，并且**连 viewport 一起清** ——
Qt 给 `QGraphicsView` 显示的 tooltip 取自指针实际悬停的那个 widget，只清 view 会在接收 hover 的
viewport 上留下旧值：

```python
panel.gview.setToolTip("")
viewport = panel.gview.viewport()
if viewport is not None:
    viewport.setToolTip("")
```

**没有做的事：** 没有把这段文字搬到 status tip、what's-this、弹窗或任何别的入口；
没有改共享 `OverviewPanel`；没有新增状态、事件过滤器、timer、缓存或组件；
没有碰 Loading / failed / ROI-Patch warning 的可见行为。

**最终值：** 成功元数据写入后 `panel.status` 仍隐藏，`gview.toolTip() == ""`、
`gview.viewport().toolTip() == ""`，两者都不含 `Full image` / `Overview`。
Loading → 成功 → failed → 成功 四步往返，每一步两个 tooltip 都是 `""`，
且 Loading 可见、failed 可见、成功隐藏。

**底部点击无回归：** 既有真机形态门重跑通过 —— 画布最底部内侧 **1 px 与 2 px** 各一次真实
`QTest.mouseClick`，各自 `navigate_requested` **恰好一次**，落点 `y > 0.8 × full_h`。

**Step0 不受影响：** 独立构造的 `OverviewPanel` 成功元数据行仍可见，且其 tooltip 与调用前逐项相同。

**四条新门 + 三项变异：** 变异 1（tooltip 挂回 `gview`）、变异 2（改挂 `viewport`）、
变异 3（成功行恢复可见）**全部转红**，每次按 SHA-256 逐字节还原。

**不宣称真机通过** —— 等待用户确认「长时间悬停不再出现提示框」。
