## 6. 本环境确实够不着的三处（这是本报告最重要的部分）

1. **没有 framebuffer / 像素证据（退出门 C 未尝试）。** offscreen Qt 下未抓取 Viewer 的
   framebuffer，也未做 GPU oracle 比对。所以"中间帧没有平移/缩放/拉伸"**只在相机与几何层面**成立，
   **像素层面没有证据**。
2. **Tissue Preview 与 Viewer 不是同一张切片。** rig 的 `_Loader` 是 512×256 的合成切片，
   而 mount 打开的是真实 19480×21804 的 `biopsy.ome.tif`。因此画出来的 Patch 坐标**不在 Viewer 的
   坐标系里**。任何"因为新 Patch 的位置而产生的"晃动，本测量抓不到。**这是最可能让复现落空的一点。**
3. **用户真实窗口尺寸、DPI、合成器与本机 offscreen 布局不同。** 本报告的几何是真实 Qt 布局，
   但不是用户显示器上的布局。

此外，两处按 §五 允许范围内的控制点，如实列明：

- **geometry persist 的完成点是驱动的**：本 rig 没有可写项目，worker 不会自行发布，
  所以由测试调用 `page._on_geometry_persist_published(outcome)`。
  **其下游全部是产品自己的链**（该函数发 `geometry_committed`，MainWindow 的槽接收并调用
  `_on_patches`）。**从未直接调用 `_on_patches`。**
- **`window.step0_output["step0_manifest_path"]` 被设为测试数据**：不绑定 handoff 时
  `_on_step0_geometry_committed` 会按产品逻辑直接 return，整条链根本不会走。那次比较本身仍在执行。

## A4. 像素证据及其取帧限制

`QWidget.grab()` 取手势前后各一帧，`1323×737`，SHA-256 **完全相同**
（`79f00bcd…`）。

## C4. submit 与 paintGL 的第一处差异

 9  submit#4   widget 611×450   → FBO 611×450
11  resizeGL   611×450
12  resizeGL   1323×737         ← widget 变大，FBO 没有
13  paintGL    widget 1323×737, FBO 611×450   ← blit_is_rescaled = True
