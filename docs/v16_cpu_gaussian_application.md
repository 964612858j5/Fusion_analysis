# v16 CPU Gaussian（cuCIM 路径）加速申请（块 CG，方案稿，待用户审批）

日期：2026-10-04。分支 `v16`，HEAD `e4ec48d`。状态：**v2，用户 2026-10-04 批准**（按独立审核意见修订：通道级实现冻结、实现单独进签名、G1b 设一致性门槛；G2 不做）。

## 1. 目标

无 GPU 环境（含将来的 macOS）下，Step0 "cuCIM"（高斯背景扣除）的 CPU 计算明显变快；Save、视图预览、floor 与亮度标定共用同一函数，一并受益。

## 2. 现状

- `core/bg_correction._cucim_cpu`：`skimage.filters.gaussian(arr32, sigma, preserve_range=True, mode='reflect')`（内部即 scipy 可分离 1-D 卷积，float32，截断 4σ），再 `clip(arr − bg, 0)`。GPU 路径为 cupyx `gaussian_filter`，算法相同。
- 光环 `ceil(4σ)`，默认 σ=50；Save 签名 `('cucim', σ, '2', path, None)`。
- 本机（16 逻辑核、10 GB）全片单通道 σ=50：1/4/8 线程 61.3/20.5/13.9 s。8 线程时已受内存带宽限制。

## 3. 实测（真实 uint8 切片；误差相对现有输出，数据范围 0–255）

| 做法 | 单块 4496² σ10/25/50/100 | 误差 | 备注 |
|---|---|---|---|
| 现状 skimage/scipy | 1.47/2.67/4.45/8.54 s | — | |
| 直接调 scipy float32 | 不变 | 逐像素相同 | 无收益 |
| **OpenCV `GaussianBlur`**（核长 2·int(4σ+0.5)+1，`BORDER_REFLECT`） | 0.28/0.79/1.98/6.86 s | 最大 1.2e-4，平均 3e-7 | 浮点累加顺序差异 |

| 降采样近似（×2/×4/×8，σ=50） | 0.63/0.12/0.06 s | 输出最大 0.012/0.060/0.244 | **改变算法** |

## 4. 方案

**G1 —— CPU 高斯改用 OpenCV（推荐，结果在 float32 舍入级别内一致）**
- `_cucim_cpu`：`cv2.GaussianBlur`，显式核长与 σx=σy=σ、`BORDER_REFLECT`，裁剪不变；无 OpenCV、含 NaN/Inf、图过小时回退现有 scipy。
- 版本标记：结果并非逐像素相同，不能沿用完全相同的签名。用现有签名机制为 CPU 高斯通道记下实现（如签名中的计算路径字段记 `cpu-cv2`），增量 Save 据此区分；TopHat 与 GPU 不受影响，不做全局版本号升级。
- 视图预览、floor、亮度标定同函数，单次调用约快 2 倍。

**G1b —— 高斯通道的 Save 用 1024 tile（测量后决定）**
- 高斯光环覆盖完整截断核，结果与 tile 大小无关（实施时逐像素验证 1024 与 4096 一致）；1024 tile 更适合 CPU 缓存：8 线程 14.6 s → 10.0 s，内存更低。TopHat 维持 4096。
- 需改 `ui/step0/search_ctrl.py` 的 tile 大小选择与 `core/bg_parallel.py` 的每块内存估计。

**G2 —— 降采样近似（不推荐现在做；如需"快速模式"另行科学裁定）**
- 10–37 倍提速，但是另一种背景估计器：须 CPU/GPU 同时采用、新算法版本 `3`、降采样网格按图像坐标对齐以免 tile 接缝、在多张切片 / 弱信号 / 小目标 / 阈值分类上重新验证。

**不做**：FFT（内存太大）、多进程、IIR / 盒滤波近似、GPU 相关工作。

## 5. 文件白名单（G1 + G1b）

`core/bg_correction.py`；`ui/step0/search_ctrl.py`（高斯 tile 大小）；`core/bg_parallel.py`（每块内存）；签名消费方若需要则 `ui/step0/step0_page.py` 中 Save 签名比较部分；测试：新增 `tests/test_bg_gaussian_cpu.py`，既有相关测试回归。

## 6. 验收

1. 误差：多通道、多切片（含 uint16 与浮点）、σ 取 1/10/50/最大值；全通道解码后的 level-0 与粗平面最大 / 平均误差，接缝处单独统计；相对误差以接近 0 的分母下限计算。
2. 下游：Step4 每细胞统计、受影响通道参与的分割结果对比。
3. 速度与内存：各方法在其最佳线程数下的时间与峰值内存；floor / 亮度标定耗时。
4. 若有条件，在目标 Mac / 笔记本上实测（不同机器内存带宽与 OpenCV 构建差异大）。
5. 版本：旧 scipy 通道与新 OpenCV 通道在增量 Save 中可区分。

## 7. 审核记录

- codex（astra low，2026-10-04）：G1 值得试，但收益主要在 1–4 线程，需在目标机器上验证；必须记录实现版本，不得沿用完全相同的签名；G2 作为近似可辩护，但一块的 ≤0.4% 不是普遍界限，须 CPU/GPU 同一估计器、网格对齐、另行科学裁定；建议测试更小 tile（已测，见 §3）。

## 8. v2 修订（独立审核，用户 2026-10-04 批准）

- **G1 批准**：同一高斯背景扣除算法的另一种数值实现；全局 `BG_CORRECTION_ALGO_VERSION` 保持 `2`。边界必须 `BORDER_REFLECT`（对应 scipy `reflect`），不得用 `BORDER_REFLECT_101`。
- **通道级实现冻结**：Save 的一个通道从第一块到最后一块只用一种实现。开始时选定 OpenCV；任何一块 OpenCV 不能处理（含 NaN/Inf、图小于核等）→ 丢弃本通道本轮结果，从第 0 块起整通道用 scipy 重算，再发布（与 GPU 失败整通道转 CPU 的既有规则相同）。**禁止逐块回退。** 视图预览 / floor / 亮度标定只作显示，可逐次选择。
- **签名**：`bg_compute_path` 仍只表示 `cpu` / `gpu`；新增 `bg_compute_impl`：CPU 高斯 `opencv-gaussian` / `scipy-gaussian`，GPU 高斯 `cupyx-gaussian`。增量 Save 签名概念上为（方法, 参数, 算法版本, 计算位置, 足迹, 实现）。旧产物无该字段：高斯按其计算位置视为 `scipy-gaussian` / `cupyx-gaussian`（即旧实现），仍可在只装 scipy 的机器上复用。TopHat 的 OpenCV 与 skimage 实现逐像素相同（P1 已验证），实现字段记为空，不使旧 TopHat 产物失效。
- **G1b 有条件批准**：同一完整通道 1024 tile 与 4096 tile 的 level-0 全图逐像素比较、所有 tile 接缝单独检查；完全一致即采用 1024，不再另行请示；不一致则保持 4096。
- **G2 不做**；FFT 不做；Mac / 少核真机有则测，不阻塞。
