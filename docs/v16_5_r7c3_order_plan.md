## 2. 三套策略（开关 `BLOCK01_STEP1_ORDER=cur|odon|hybrid`；测量期间默认 cur；**用户 2026-10-16 选定默认 hybrid**）

### 2.1 共同规则（odon、hybrid；cur 完全不走这些新路径）
- **目标层**一律是 admission 后的实际层 `a.level`；辅助层不参与 admission，不会迫使目标降粗。`a.coarse_only` 或 `a.base_overflow` 时与 cur 相同（不请求辅助层，门与上传照现行）。
- **辅助层**（target+1、阶梯）只取比目标粗、比最粗层细的层；目标已是最粗层或最粗层−1 时为空。
- **额度（预留制）**：每通道的 carry（`Admission::carry`）= 已保留替代块的字节 + 未完成辅助块的**预留**字节 + 余额。`plan_channel()` 先 `retain()`（现行），再只用**余额**按"离目标层近的层优先、层内离中心近的优先"给新辅助块并记预留；辅助块交付时从"预留"转为"保留"，字节数不变，不因交付腾出余额；已保留或已预留的键不再分配。余额只在 `plan_channel()` 时重算（换视野、换通道、粗层完成——现有调用点），不在交付时追加分配，因此不会逐块空转重发。
- **分开记账**：辅助块记在 `FinePlan` 新增的 `aux` 集合，不进 `expected`；第 2 步 limited 的积压判断仍只看目标缺块（`expected`）；画面要的辅助块不当预读（第 2 步 `issue()` 已剔除）。
- **顺序是排队优先级，不是完成屏障**：odon / hybrid 的 `issue()` 队列按（层次序 → 离中心距离 → 位置 → 通道）排；worker 照现行取第一个可开始的。cur 的排序（粗层通道外循环在前，再目标层近到远）不变。
- **重发与撤销**（仅 hybrid 需要）：目标层某通道 `expected` 被交付清空时，规划器撤掉该通道的 `aux`（未交付的）并置"需要重发"。消费点两处：(1) `paint()` 收图后见标志即 `issue()`（与现有 `replanned` 同路径）；(2) `issue()` 内先交付同步缓存命中，若因此置了标志，就重算一次请求再提交队列（最多两遍，第二遍只会更少）。`issue()` 结束时清标志；标志只在确有撤销时置，不会空转。撤销语义沿用现行：新队列替换旧的"仍需要"集合，已在读的被撤辅助块按现行规则作废（可能提前取消、读完丢弃），不改 pool。
- **sticky ceiling**（odon 用）：状态放 `Planner`：`prev_target`、`ceiling`；admission 目标层号变细 → `ceiling = max(ceiling, prev_target)`；变粗 → `ceiling = target`；不变 → 不动；换片（新 Planner）清空。阶梯 = target+1..=ceiling（与 target+1 去重），一律受余额限。
- **Odon adaptive（两个分支）整体不纳入本步**：本步所有通道数用同一规则（§4.2）。
- **上传与显示分开**：`drawn()` 拆为 `candidates()`（该进 GPU 的块）与显示许可 `shown(c)`。
  - cur：`candidates()` 与现行 `drawn()` 完全相同（粗层整层未交付时为空，因而也不上传），`shown` 恒真——逐帧行为与现在相同。
  - odon / hybrid：`candidates()` = 已交付的粗层块 + fine 保留块 + 已交付的辅助块，照现行做"比目标更细的替代块在目标格都上 GPU 后剔除"，排序粗到细；上传列表来自它（预算不变）；上传后 compose 照现行**再算一次** candidates，只画 `shown` 为真的通道。

### 2.2 cur（现行，行为不变）

### 2.3 odon
- 请求层：目标；target+1；阶梯；最粗层。
- 范围：目标层可见（+ 预读）；target+1 与阶梯各层可见外扩 1 块；最粗层**先**可见外扩 1 块、**后**补齐整层（§4.1，用户已同意）。
- 顺序：目标 → target+1 → 阶梯（细到粗）→ 最粗层可见外扩 → 预读 → 最粗层其余。
- 显示：`shown` 恒真（不等整层）。这是"不等整层发布"，不承诺每个到达 CPU 的块当帧上屏（上传仍有预算）。
- 缩小：保留现行 carry，不加 400 ms floor；视觉效果由缩小路线验证（§4.3）。

### 2.4 hybrid
- 请求层：目标；target+1 **只在**该通道目标层仍有缺块（`expected` 非空）时于余额内请求，目标齐了即撤（2.1）；最粗层。无阶梯。
- 范围、顺序：同 odon（去掉阶梯）。
- 显示许可（首次出现门）：该通道"本次启用以来"第一次满足**评价区几何覆盖齐**时打开，之后一直打开（平移、缩放不再隐藏）；取消勾选、换数据来源、换片时重置。评价区为空（视野全在片外 / ROI 外）时门保持关闭。
- **几何覆盖齐的判定（精确）**：
  - 评价区 = 视野矩形 ∩ 片范围 ∩ ROI 外接矩形（核心里 ROI 就是这个矩形 `corrected.rs:53`；多边形模板只在绘制时遮挡，块按外接矩形读取与截断，所以覆盖外接矩形即覆盖多边形内部，偏严）。
  - 取该通道 `candidates()` 中已上 GPU 的块，各取其**几何有效矩形**（块矩形按片边、ROI 截断后的范围，即 `Tile.valid` 的 Rect；`Valid::Finite` 视为整块）。约定："覆盖"指几何覆盖；块内非有限值由着色器逐样本跳过，不算缺块，本步不扩 validity 系统。
  - 用评价区边界与所有块矩形的边切分评价区为小矩形；每个小矩形都被某块矩形完全包含（与块求交即可判断，因为切分线包含块边，小矩形要么整个在块内、要么整个在块外）即覆盖齐。块数几十量级，开销小。

### 2.5 本步保证与不保证
- 保证：每个已启用通道照旧请求最粗层整层（odon / hybrid 只是排后），整层到齐后与现行一样常驻在规划器中（A9-6 的"该通道粗层常驻"部分）。
- 不涉及：其他未启用通道的后台预热（A9-6 的另一部分）不在本块范围，不改。

## 5. 评价方法（阈值在跑三套之前固定，跑后不调）

### 5.0 共同定义
- 像素差 = RGB 三分量差的最大值（0–255）；T = 4。格 = 32×32 屏幕像素，按看图区左上角对齐，不足一格的边角不计。
- **参考终态 R0 由标定得到，不用被测运行自己的末帧**：每条路线先用 cur 策略、热读跑一次标定（`calib_r7c3.sh`），稳定区间内要同时满足：程序内帧记录（`BLOCK01_A9_DRAW_LOG`）里启用通道集合完整、当前目标集合不变，且每帧报告 `shown == wanted`（`frame.rs:228`，按当前 GPU 驻留核对，不是候选列表）；这些帧的上屏时刻与截图关联，期间连续 1 s 截图逐像素相同，取一张为 R0；同时固定该路线的有效格集合。三套策略都对同一 R0 评价；被测运行的末态与 R0 在有效格上不符（任一有效格不为 B）记"终态不符"，作为失败结果保留，不剔除。

### 5.1 勾选新通道（tick 路线）
- **场景**：打开项目，启用固定通道集合（4 个，固定颜色、窗、Gamma、显示模式），走到固定位置（z1 1.315 倍、z2 2 倍，各一个组织中央位置），等帧记录显示目标层全部在画、再静止 1 s；清页缓存；勾选预先选定的通道（候选 CD8，标定时确认有效格 ≥ 50）。注入是 `setChecked()`（`scripts/a9_drive.py:376`），起点称"勾选动作时刻"（注入记录的时间戳）。
- **运行有效性**（只因测量本身失败才重跑）：勾选前 trace 中该通道没有任何 req / read；看图核心 sha1、ORDER、PREFETCH 与预期一致。
- **截图**：`a9_framecap.py` 60 Hz，勾选前 0.5 s 到勾选后 6 s；随后同一时钟 5 Hz 继续到勾选后 20 s。时长一律用截图实际时间戳。
- **分类**（标定时用勾选前的 Bf0 与 R0 固定）：有效格 = 格内 ≥50% 像素 |Bf0 − R0| > 2T（据此 A、B 互斥）。被测运行每帧每有效格：A = ≥90% 像素与本次勾选前末帧 Bf 差 ≤T；B = ≥90% 像素与 R0 差 ≤T；其余为 M。报告有效格数量与分布图。
- **指标**：首次变化（第一帧有非 A 有效格）；持续出现（此后到 20 s 所有有效格一直非 A 的起点）；持续清楚（此后到 20 s 一直全 B 的起点；20 s 内未达记"未完成"，只给下界）；出现不均匀：首次变化到持续出现之间 A 与非 A 并存的时长与最大 A 面积占比；从中心向外：各有效格首次非 A 时间与离视野中心距离的秩相关（有效格 < 20 或首次时间全相同记 N/A）；无效格瞬态变化比例（只报告，不归因）。三项时间合起来解释。

### 5.2 跨级放大 / 缩小（zoom 路线）
- **手势**：滚轮每格 ×1.07（`ui/step1_viewer_host.py:586`），放大 11 格（约 ×2.1）、缩小 11 格（约 ×0.48），注入工具常规速度；起点视野选在使 admission 目标层号确实变化至少 1 层的位置（标定时核验）；每轮从帧记录核对目标层确实变了，未跨层的轮次作废重跑。
- **截图**：`a9_framecap.py` 60 Hz 从手势前 0.5 s 到停手后 3 s，随后 5 Hz 到停手后 15 s；`a9_stopshots.py` 只用于停手后固定时刻的抓图，差异由新 `eval_r7c3_zoom.py` 对 R0 计算（不用 `a9_shotdiff.py` 的末张参考）。
- **有信号格**（标定时固定）：R0 中 ≥50% 像素与看图区背景色差 > 2T 的格。
- **指标（只在停手后算）**：持续清楚时间（全部有信号格为 B）；50 ms 时最差 64×64 小块对 R0 的差异（按实际最后一次注入时刻计，用 stopshots 记录的 `from_last_ms`，不信文件名）；"信号欠显（代理指标）"= 有信号格中 ≥90% 像素与背景差 ≤T 的格占比，配合程序内每帧记录（目标块数 / 已上屏数）解释，不称几何空洞。手势中的截图保留，只做人工逐帧检查（相机在动，不与 R0 比）。

### 5.4 环境与版本核对
- 不直接调用 `run_check2.sh`（它会装回旧安装包）。`run_r7c3.sh` 复用其真实项目检查路线，固定 ORDER=cur、PREFETCH=limited：批前、每 18 次、批后各跑一次；重复帧 > 10% 即暂停整批并请用户收窗口，记录受影响的批次区间。

## 6. 数值自定（用户 2026-10-16：避免照搬 Odon 的常量）
Rust 方案风险第 9 条要求"只参考设计，不拷代码和常量"。第 2 步 odon 预读用了 Odon 的数值。已从第 2 步批 1 的 trace 核对哪些数实际起作用（odon 运行，10 个启用通道）：每次新预读最多 256 —— z1 S1 / 反向拖最多 160、含 S2 最多 178，均未触顶；**z2 S1、反向拖触顶 256**；第二圈门槛"pad1 ≤ 16 个位置" —— pad1 在 z1 为 0–25、z2 为 0–20 个位置，门槛起作用；第二圈上限 48 个位置 —— 实际最多 20 个位置，**从未触顶**；关第二圈的通道数 16 —— 启用 10 个，16 与 32 无区别、8 会关。
- 数值改为可由测量环境变量覆盖（只供测量；默认值测后按我们的结果定）。odon 预读的数在 `PREFETCH=odon` 下测，limited 键数在 `PREFETCH=limited` 下测；ORDER 固定为第一批选出的策略（第一批未定时用 cur）。
- 一次只改一个数，其余取基准；只列能区分的值：
  - 每次新预读上限 {128, 256, 512}：z2 S1、z2 立即反向拖；
  - 第二圈门槛 {8, 16, 32} 个位置：z1 S1、z1 立即反向拖；
  - 第二圈上限 {16, 48}：在门槛 32 下测（16 会触顶），z1 S1、z1 立即反向拖；
  - 关第二圈的通道数 {8, 16}：z1 S1、z1 立即反向拖（32 本项目测不到，记"未测到"）；
  - limited 键数 {24, 48, 96}：z1 S1、z1 立即反向拖。
  - 机械盘 + 合并 OME-TIFF，2 轮，独立新批次（不复用旧基准）：8 个非基准条件 × 2 路线 × 2 轮 = 32 次；odon 基准（z1、z2 各两条路线）× 2 轮 = 8 次；limited 基准（z1 两条路线）× 2 轮 = 4 次；合计 **44 次**（第二圈上限 16 以"门槛 32、上限 48"为对照，已在其中）。每次记录实际启用通道、第二圈是否产生、各上限是否触顶。
- 单变量筛选后，对最终组合做一次定向确认（同路线 2 轮）。
- 测不到的数（关第二圈通道数 32 以上、≥16 通道相关）标"未测到"，保留现值并写明来源与原因；不写"由本轮测量选定"。
