## 0. 一句话

在 Step1 里，满足条件时（原始 8 位通道、Overlay、全片 ROI），由 Rust 完成"要哪些块 → 读 → 缓存 → 送显卡 → 画"这一整条路。Python 只交镜头和显示设置的快照。然后和 Odon、和 `v16-final` 同场配对实测，回答"Rust 能不能接近 Odon 手感"。

## 1. 范围

**做**：原始 uint8 通道、Overlay 模式、全片 ROI；平滑设置和基线一致；现有 Python 的准入、粗层、细层、保留、替身规则全部照搬（§3）。

**不做**：
- u16 / f32、Fusion、校正产物、标签、ROI 多边形或非全片 ROI、Step3、预分割 montage；
- 笔记本、Windows 自动构建；
- 69 通道（不是 S-Raw 的继续条件，留到服务器验收）；
- 逐通道回退绘制、空闲时预分配显存的定时器：改为初始化时一次分配。

**Rust 模式何时启用**：
- 三个条件同时满足：环境变量 `BLOCK01_STEP1_BACKEND=rust`、内核能导入、当前状态在支持范围内。默认仍是旧路径，不加任何界面。
- 进入 Step1（以及换 ROI、换来源时重建查看器，这一步本来就会重新选后端）时不满足，就用旧路径，终端写明原因。
- 运行中变成不支持（切到 Fusion、勾选了校正通道），按 §6 回退到旧的 Python GPU 层。回退只有这一个方向，本次查看期间不再切回 Rust。

## 2. 新旧职责

| 环节 | 旧路径（Python） | 薄切片（Rust 模式） |
|---|---|---|
| 镜头、滚轮、拖动 | pyqtgraph + `ExploreController` | 不变，仍是唯一镜头 |
| 选哪一级 | 控制器（就近取对数，带回滞） | 不变：Python 把控制器的 `level`、`bbox_l0`、`epoch` 交给 Rust，Rust 不重算级别 |
| 准入、规划、替身、保留 | `Step1GpuBinding` | Rust（`admit.rs`、`plan.rs`） |
| 请求、读图、解压、缓存 | `TileScheduler` + 8 个 Python 线程 + `LRUByteCache` | Rust 线程池（6 个）+ Rust CPU 缓存。旧调度器不启动（§5） |
| 送显卡、画 | `Step1GpuLayer` + `VirtualCompositor` | Rust（`gpu_store.rs`、`vt.rs`、`render.rs`） |
| 显示映射、缺失窗口补算、提示 | 挂载 | 不变 |
| 测量 | `tile_trace`、`perf_trace`、`coverage_probe`、`read_ledger`、调度器 `idle()` | Rust 提供等价信息，接到原来的出口（§8） |

## 3. 照搬的规则（以现有 Python 为准）

### 3.1 几何和有效区域（`geom.rs` 对照表，f64 按同样次序算，最后才转 f32）

| 量 | 现有算法 | 出处 |
|---|---|---|
| 规划用降采样 | 取整 `round(h0/hL)`，各轴同一个数 | `raw_tile_provider.level_downsample`、`binding._level_ds` |
| 放置用降采样 | 不取整、分轴 `(h0/hL, w0/wL)` | `level_downsample_yx` |
| 视野覆盖的块 | `bbox_l0`（y0, x0, y1, x1；已截到图像内、截断成整数）÷ 取整降采样，逐角 `int()`，再按 512 覆盖 | `request_planning.visible_tiles_for_viewport`；非理想级同 `_candidate_keys` |
| 块的形状 | 截到这一级的尺寸，**边缘块不补到 512** | `step1_viewer_host._level_rect` |
| 块的世界矩形 | `x0 = tx·512·ds_x`，`x1 = x0 + 宽·ds_x`（y 同理） | `binding._world_rect` |
| 有效区域 | 块内半开矩形；0 是有效值。全片 ROI 下等于整块；"没有有效区域"和"整块有效"要区分开 | `native_tile`、`step1_gpu_layer.RawPlane` |
| 级别槽 | `round(ds, 9)` 作键，`u_level_a = 512·ds_x` | `step1_gpu_vt.py` |
| meta / 参数 | 和 Python 写入的 float32 数完全一样 | `vt._sync_meta`、`upload_params` |

### 3.2 准入（`_admit_new`）

从控制器选的级别往粗找，第一级同时满足以下三条的就选它：
- 每通道细块字节不超预算；
- 块数不超过 256；
- 加上全部粗层后不超总预算。

都不满足就只画粗层，并报"分辨率受限"。完整照搬：
- 字节按整格（512²）计；
- 总预算先扣掉纹理数组的块余量（`array_slack_bytes`，依赖 `GL_MAX_ARRAY_TEXTURE_LAYERS`）；
- 最粗一级时粗层和目标块的重叠不重复计；
- 剩余额度按通道平分，作为替身的携带额度（carry）；
- 最后按总预算裁一遍。粗层本身超预算时保留上一帧，并报"基础层超预算"（`base_overflow`）。

最后这次裁剪在 Rust 里降为断言加记录，因为准入已经保证不超。

### 3.3 粗层和目标块

- 每个活动通道请求最粗一级的整层。该通道的块全部上了显卡，才一次性显示。
- **粗层整层先于任何细块入队**，否则原子显示会被细块挤到后面。
- 目标块就是所选级别覆盖视野的块。

### 3.4 保留和替身

- 目标块永远保留。
- 其他块只要和"准入选定的块覆盖矩形"相交，就作为替身，按"离目标级近的先、再按行列"占用携带额度。注意比的是块覆盖矩形，不是镜头矩形。
- 不相交的块，从显卡页表里去掉，但 CPU 缓存里还在。
- **比目标级更细的替身**：直到它覆盖的每一个目标格都已上显卡，才不再画（`_drawn_fine`）。粗于目标级的替身照画，由着色器"每个像素取最细的有效级"决定。

### 3.5 请求顺序

- 方案 §5.1：由近到远、同位置各通道一起。
- 旧路径是按通道名、再按（级别、行、列）。顺序不影响稳定后的画面，但会影响停手 50 ms 的截图和手势中的响应。
- 所以 `plan.rs` 留一个**只用于测试的顺序开关**：热状态多跑 1 轮"旧顺序"，用来拆分收益来自引擎还是来自顺序。

### 3.6 画

- 移植虚拟纹理单遍着色器的 uint8 / Overlay 部分，算式逐行照搬。
- **平滑**：只在任一轴上一个原始像素比一个屏幕像素宽时启用；先对原始值做双线性混合，再做强度映射；邻块取同一级；无效样本丢弃后重新归一；通道按同样次序累加。开关来源 `gpu_memory.smooth_pixels()`。
- **合成流程**：RGBA32F 的累加纹理 → Overlay 最终合成（`PASS_FINAL_OVERLAY`）→ RGBA8 的 `final` → 按四舍五入后的设备像素尺寸、用 `GL_NEAREST` 拷到 `defaultFramebufferObject()`。
- **全片 ROI 也要跑最终合成**，只是不开裁剪。
- 逐像素比较两边都读 `final`。

## 4. 每帧怎么跑

1. **两类输入分开**：
   - `set_view(level, bbox_l0, epoch, input_time)`：规划用。同一 epoch 不重新规划，但 `gesture_quiet`（epoch 不变）要更新"输入已停"的状态。
   - `set_camera(world_rect, device_size, dpr)`：画用。world_rect 是 `viewRange()` 的浮点值，每次 `sigRangeChanged` 和尺寸、缩放比变化都要传，即使 epoch 没变。

   两者都在 GUI 线程同步调用，保持 Python 锁，**不碰 GL、不等线程池的锁**（"当前需要"集合用原子交换）。规划耗时实测，不预设"只要微秒"。初次挂载和恢复时各发一次完整快照。
2. **Rust 规划**：准入、目标块、保留、替身，然后把缺的块按顺序交给线程池。
3. **读图线程**：读、解压、放进 CPU 缓存，再放进有界结果队列，然后发通知（"读空 → 确认 → 取工作"）。
4. **paintGL**：**整帧一份预算**，取结果、分配格子、上传、更新页表、画都算在里面。
   - 有输入（最近 60 ms 内）时，上传部分沿用基线的 1.5 ms；
   - 没有输入时整帧不超过约 12 ms；
   - 粗层原子显示的上传不受预算限制，单独记录；
   - 具体数值实测定，前提是界面心跳 < 20 ms。

   全程保持 Python 锁。
5. 没传完的下一帧接着传，Rust 再发通知。
6. **暂停或隐藏**：不规划；读图线程读完手上的就停（结果队列满了就等）。恢复时发一次完整快照并 `update()`。关闭时先停通知、再停线程，GUI 线程不等正在进行的读。

## 5. "用到才启动"的调度器包装

放在 `ui/step1_viewer_host.py`，是一个新的小类，**显式列出**每个方法，不用通用的懒加载：

| 调用 | 建立之前怎么处理 |
|---|---|
| `request` | 真正建立并启动 `TileScheduler`，再转交（只在回退到旧路径之后才会发生） |
| `cancel_generation` | 不做事 |
| `notify_when_idle` | 立即同步回调 |
| `idle()` | Rust 模式下返回 Rust 线程池是否空闲（测量工具判断画面稳定要用） |
| `raw_cache`、`corrected_cache` | 原样提供（`build_step1_stack` 本来就建好了） |
| `warmed_workers`、等待数、挂起数 | 返回 0 |
| `shutdown` | 终止；之后不再建立 |

建立以后，以上调用全部转交真调度器。

- Rust 模式下，控制器自己的请求在初次设定视野和 Qt 初始化之前就关掉。
- 测试检查的是**这个 Step1 的调度器**没有启动，而不是全局没有 `tile-io-*` 线程，因为 Step0 可能自己有。
- Step0 不动，`viewer/scheduler.py` 不动。

## 6. 运行中回退（Rust → 旧的 Python GPU 层）

1. 触发点在 `refresh_display` / `set_mode` 里面，用 `singleShot(0)` 推到下一轮事件循环执行，避开 `_gpu_refreshing` 的重入保护。
2. 先做 `_stop_gpu_backend(restore_controller=False)` 的 Rust 版：停通知 → 让读图线程退出 → 在当前上下文释放 GL → 销毁控件。
3. 再走原来的 `_start_gpu_backend`，建旧层和旧绑定。
4. 结束时的状态：
   - 控制器请求仍是关的；
   - 底层标记隐藏；
   - 场景不重画；
   - 镜头、显示、来源保持不变；
   - 显示和来源信号重新连上；
   - 遵守暂停状态；
   - `mount.gpu_layer` / `gpu_binding` 换成新的，并在 `gpu_memory` 登记；
   - Rust 一侧报告剩余资源为 0。
5. Python GPU 也起不来，就退到 CPU：照原来的路径加载全片概览，并恢复控制器请求。

**兼容**：`Step1CoreBinding.stats()` 提供挂载、主窗口用到的全部键。`descriptor_history` 提供轻量记录（不含图块数据），供 `main_window.py:5357` 的进入记录使用。

## 8. 验证

### 8.1 测试可比性的先决条件（开测前逐条确认，不满足就停）

1. §44 场景的 20 个通道都是原始来源；
2. ROI 是全片；
3. 在全片 ROI 下，用旧路径截"有裁剪"和"无裁剪"两张逐像素比较，包括视野越出片子边缘、alpha 通道；
4. 每轮核对 `gpu.frame channels=20`；
5. 双方相机、强度映射、平滑、显示设置、缓存预热方式、测量开关都相同，记录在报告里。

### 8.2 自动测试（GPU 测试一条一个进程）

- **准入、目标块、保留、替身**：同一批镜头，加上缩放刚好在级别边界的情况。Rust 和 Python 喂同样的输入：级别尺寸、预算、块余量、`GL_MAX_ARRAY_TEXTURE_LAYERS`、已有的块。逐项结果相同。
- **稳定画面逐像素一致**：两边都等到"已稳定"（目标块全部上显卡、没有在途请求），读回 `final` 比较。覆盖 3 通道和 20 通道、平滑开和关、多个缩放级别、片子边缘。
  - qptiff 那 62 块坏尾块：比较的视野先避开它们。
  - 落在这些块上的视野，单独拿 tifffile 的读法作参照报告，不放宽整体标准，也不修冻结基线。
- **生命周期**：进入、离开、暂停、恢复、换来源、运行中回退（Fusion、勾选校正通道）、关闭。
- **调度器**：Rust 模式下这个 Step1 的调度器没有建立；回退后第一次请求时才建立。
- 第一轮的测试继续通过。
- **定向回归**：挂载、宿主、GPU 接管、预分割 montage、Step3 相关模块，4 个并行。

### 8.3 实测（显示器 :1，测前关掉 VGA-2-1，图形测试和性能测试不同时跑）

- **20 通道**：热 5 轮、冷 2 轮。冷读受机械硬盘限制，单独报告，不作判断依据。三方同场交替：Rust、`v16-final` 旧路径、Odon（重新测，不只引用历史数据），每轮交换先后。
- 热状态多 1 轮 Rust"旧请求顺序"（§3.5），用于拆分收益来源。
- 3 通道 2 轮作保护。
- 用 §44 的全部工具：停手稳定时刻、手势中响应、程序内各阶段、目标层完成时间、最差 64×64 小块。
- 指标说明：基线的"热放大目标层完成 527 ms"来自程序内记录，"截图稳定 800 ms"来自截图，两者是不同指标，分开报告。
- **用户第 3 问**：同一批手势里，单独记录还留在 Python 的部分各花多少时间：
  - pyqtgraph 的滚轮处理（`wheelEvent`）和拖动处理（`mouseDragEvent`）；
  - `ExploreController._on_range_changed`；
  - Tissue Preview 视框重画（`publish_view_rect`）；
  - 新层的 paintGL 外壳。

  嵌套的计时段扣掉重复部分。视框重画发生在停手 80 ms 之后，所以"手势中"和"停手后"分开下结论。

### 8.4 继续的条件（方案 §8，同时满足才进入下一阶段，否则停下报告）

1. 向下拖动、单格缩小、甩动的停手稳定中位数 ≤ 50 ms，或比基线至少减半；
2. 热放大目标层完成 ≤ 200 ms（基线 527 ms，同一程序内指标）；
3. 手势中响应的中位数、95% 线、超过 50 ms 的次数都不比基线差；
4. 最差 64×64 小块差异和目标层真实覆盖同时达标。

另外报告：界面心跳间隔的 95% 线和最大值（目标 < 20 ms）、每次 paint 的耗时、实际呈现帧间隔。

## 9. 风险和工期

**风险**：
- 剩余 Python 成了瓶颈：报告数据，另立块。
- 逐像素不一致：定位到具体环节，不放宽。
- paint 挡住输入：按预算拆分，并报告。
- 回退出错：有专门测试。
- 范围膨胀：只搬 §3，遇到需要新机制先停下问。

**工期：10–13 个工作日**（第一版写的 7–10 天偏乐观，两份审核都这么认为；按子任务加起来已是 9.5–10.5 天）：

| 线程池、缓存、通知 | 1.5 |
| 显卡存储、虚拟纹理、绘制、逐像素对齐 | 3 |
| Python 层、绑定、挂载、回退、调度器包装、测量钩子 | 2 |

## 10. 审核记录（第一版 → 第二版）

两份审核结论一致：方向、边界和回退顺序与 v2.1 一致，没有范围膨胀；按第一版开测，会卡在测量工具判断不了画面是否稳定、逐像素对比失败、准入在级别边界上差一级这几处。全部采纳：

- **测量钩子**（§2、§7、§8）：测量工具判断画面稳定靠 `coverage_probe` 发布、`read_ledger` 读盘静默、调度器 `idle()`，Rust 版要提供等价信息；`tile_trace` 的字段和原始时间戳要保留。
- **几何和格式逐表达式照搬**（§3.1、§3.6）：取整和不取整两种降采样、边缘块不补零、有效区域的语义、float32 的 meta、RGBA32F → `final` → 拷屏、无 ROI 也跑最终合成。
- **准入的全部输入**（§3.2）：块余量、去掉重叠、携带额度、最后裁剪、基础层超预算。
- **替身规则更正**（§3.4）：替身覆盖的目标格要全部上了显卡才不画；保留看的是块覆盖矩形，不是镜头矩形。
- **请求顺序会改变配对的含义**（§3.5、§8.3）：加测试开关做归因；粗层先于细块入队。
- **两类输入**（§4.1）：画用浮点视框，规划用控制器给的级别；同一 epoch 的处理；尺寸和缩放比的更新。

- **回退的最终状态和兼容接口**（§6）：`singleShot(0)` 延后；`descriptor_history` 和 stats 的键；换 ROI 本来就会重建查看器，不算运行中回退。
