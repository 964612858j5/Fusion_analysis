上级：R6 调查（简报 `a9_bench/r6/早上先看_R6结果简报.md`，codex 原因分析 `a9_bench/r3work/codex_r6cause1.out`）；R7a（分段计时，先做）。
用户 2026-10-14 决定：
- 只针对校正过的通道；
- 看图用的多层数据用 16 位；

## 0. 要解决的问题（R6 已证实）
- 真实项目冷读拖动时，73–97% 的糊块，所需图块在那一刻还在排队或正在读。上传和画图几乎不占。
- 读得慢的原因：
  1. 校正结果是 32 位浮点、1024×1024 一块，一次读取要解压 4 MiB，取其中 1 MiB；
  2. 同一块被不同屏幕图块重复解压（R6：270 次读取涉及 135 个不同块，平均 2 次）；
  3. 程序自带的解压可能比成熟实现慢（初测 4.1 ms/块 对 numcodecs 0.74 ms/块，条件不同；R7a §2 用同一批块、单线程、同样输出重新比较）；
  4. 读取线程：Rust 里写死最多 6 个（`pool.rs:157`、`viewer/memory.rs:49`），10 个通道时排队 p95 达 120–320 ms。
- 等待期间只能用缩小 32 倍的粗层顶替。原因：
  - 规划器只请求"最粗层 + 目标层"（`plan.rs` `plan_channel`、`plan/draw.rs` `wanted`）；中间层只有之前读过、恰好保留下来时才会画。
  - 校正结果磁盘上也只有 32 倍这一层（`corrected_coarse.zarr`）。

## 1. 分两步，各自单独启动
### B1 读取路径提速（不新增数据）
**B1.1 解压后的存储块复用（新增缓存，本计划申请用户批准）**
- 作用范围：每个读取池一个（即每个看图窗口一个），读取线程共用，随读取池和数据来源一起销毁。来源重新绑定时整个丢弃，不另建身份系统。
- 键：读取池内实际数组的标识（数组目录路径）+ 块坐标。同一通道的全分辨率、旧粗层、各 display stride 是不同目录，自然区分。
- **预算不加大，从现有额度里划出**：
  - 现有"校正图块缓存"额度（`corrected_cache_bytes`，默认 2 GiB）里划出 256 MiB 给块缓存，图块缓存相应减少 256 MiB；
  - 实现：创建读取池时把默认 2 GiB 拆成 1.75 GiB 图块缓存 + 256 MiB 存储块缓存，`cache.rs` 的淘汰机制不变；
  - `viewer/memory.rs` 的总上界不变，只是多报一项，便于核对；
  - 关闭块缓存（开关为 0）时，图块缓存恢复为完整的 2 GiB。
- **记账**：
  - 解压前先为这一块预留它的字节数（解压中），完成后转为缓存存活字节；
  - 被淘汰但仍被线程引用的块继续计入，引用释放时扣除；
  - 解压中、存活、被引用三项分别报告，不重复计。
- **满了怎么办**：额度用尽、而且所有块都还被引用时，新解压的块不放进缓存，直接给请求它的线程用完即弃（照旧行为），不等待、不超额。
- **记账分清两类**：
  - 可缓存的块：预留、驻留、淘汰后仍被引用，三项合计受 256 MiB 限制；
  - 绕过缓存的临时块：算在现有读取线程工作额度（`WORKER_MEMORY_BYTES`）里，不进缓存额度，也不重复计。
- **统计出口**：新增几项写进现有 `core.stats()`（`py/stats.rs`，只加字段）：缓存驻留、解压中、被引用、命中、未命中、绕过次数。
- **并发**：
  - 同一块同时未命中时，只让一个线程读和解压，其他线程在这一块的等待点上等；不用全局锁包住读盘和解压。
  - 等待点在这些情况下都会结束：解压成功（等待者直接用结果）、读取失败（等待者自己重读一次，失败照现有规则上报）、请求被取消（等待者检查自己的请求是否仍需要）、窗口关闭（`close()` 同时唤醒所有等待点，等待者退出）。
- 关闭开关：`BLOCK01_STEP1_CHUNK_CACHE=0`，回到现在的行为。
**B1.2 更快的解压**
- 由 R7a 的读取分段决定：如果 LZ4 是主要部分，就改成成熟实现：
  - `lz4_flex` 纯 Rust；或 C 库 `blosc`，用 C 库时固定库内线程数为 1，避免和读取线程叠加。
  - Blosc 容器解析和 unshuffle 仍用现有代码（现有 unshuffle 已有 SSE2）。
- 如果是读文件或拷贝为主，改对应部分。
- 选型依据：R7a §2 的同条件比较。新依赖只限这一个，写进 `Cargo.toml`。

**B1.3 读取线程数**
- 把写死的上限改成配置，`pool.rs` 和 `viewer/memory.rs` 两处同步。
- 测 6 / 8 / 12 三档：记录实际线程数、峰值内存、两个窗口同时存在的情况，以及纯原图项目（OME-TIFF）不变差。
- 默认值由测量决定，不预设。

**B1 文件白名单**
- Rust：`zarr_v2.rs`、`blosc.rs`、`lz4.rs`（或替换）、新 `chunk_cache.rs`（≤ 约 300 行）、`pool.rs`、`pool/worker.rs`、`viewer/memory.rs`、`py/config.rs`、`py/stats.rs`（只加统计字段）、`viewer.rs`（配置字段）；`Cargo.toml` 和 `Cargo.lock`（只在选新解压库时，只做这一个依赖的机械更新）。
- Python：`ui/step1_core_binding.py`（配置）。
- 测试：新 `tests/test_v16_5_r7b1_*.py` 和 Rust 单元测试。
- 不改请求顺序、上传预算、显存规则；不改原图读取的结果。

### B2 校正通道的中间层（16 位），加"先要一个便宜的过渡层"
**B2.1 数据：沿用现有"保存的粗层"机制，从 1 层扩到多层**
- 现状：
  - Python（`viewer/step1_source.py` `coarse_plane(channel, stride)`）和 Rust（`corrected.rs` `Plane`，按 stride 存）都已经按"缩小倍数（stride）"组织粗层；
  - 只是磁盘上只有 stride 32 一个数组，而且只认 32 位浮点。
- 新目录 `corrected_display.zarr`（和 `corrected_coarse.zarr` 并列），布局：
  - `<ROI>/<通道>/s<stride>`，每个 stride 一个数组；
  - 组上写 NGFF 0.4 `multiscales` 元数据（axes y、x；每层 scale = stride，translation 按块原点），供外部工具查看；
  - 程序读取不靠 NGFF 元数据，靠每个数组的身份属性：沿用 `coarse_plane_identity`，加上 dtype、stride、块原点、`source_identity`，最后写 `complete`。
- stride 取值：等于原图金字塔各层的规划倍数（`geom.rs` `ds_planning` = round(h0/hk)），不用"层号的 2 次方"。
  - 用户 TMA4：2、4、8、16、32。
  - 块网格从全分辨率原点按 stride 划分，和现有粗层一致（`coarse_block_range`）。
- 格式：16 位无符号整数，512×512 一块，blosc-lz4 + shuffle。
- 优先级：同一 stride，`corrected_display.zarr` 有效时用它，否则用 `corrected_coarse.zarr`（stride 32），再否则现场缩小（现有行为）。

**B2.2 数值规则（不改科学数据）**
- **资格**：生成前检查该通道整个现有矩形样本域（校正数组的全部像素，不先过滤 NaN）：
  - 全部有限、都在 0–65535 之间、都是整数，才生成；
  - 只要有一个非有限值，或不在范围内、不是整数，这个通道就整体不生成，日志写明原因，看图照旧。
  - 数组范围以外的无效区照旧靠几何范围恢复（同现有粗层）。
  - 不做缩放。
- **各层取值**：
  - 每层都直接对全分辨率有效样本求平均（同 `box_downsample_valid`），最后只四舍五入一次；
  - 不用"上一层再平均"，避免舍入累积；
  - 没有有效样本的块记为无效（同现有规则）。
- **误差说明**：各层是"平均值四舍五入"，不是无损。源值误差 ≤ 0.5。显示时的误差会被显示范围、gamma、权重放大，所以验收分开定：
  - 源值误差 ≤ 0.5；
  - 有效区域完全一致；
  - 显示差异另行报告。
- **读取**：Rust `zarr_v2.rs` 增加读 `<u2`，读入后转成现有 32 位浮点图块，后面的 NaN/有效区、上传、显存机制都不变；不新增 GPU 格式。Python 路径同样认 `<u2`，转成浮点。

**B2.3 生成（有界、可取消、保护来源）**
- **新项目**：Step0 背景校正完成时，在现有粗层生成的同一处（`ui/step0/search_ctrl.py`）一起生成，用后台线程。
  - 按块带（slab）流式处理：一次读入若干行全分辨率块，同时累加所有 stride 的输出，写完就释放。
  - 峰值工作内存上限 1 GiB/通道，可配置。不用现有"整层 float64 累加器"的方式（对 59040×35520 的图，仅 stride 2 一层就约 7.8 GiB）。
- 沿用现有规则：
  - 来源重写前先让旧 sidecar 失效；
  - 写完最后才写 `complete`；
  - 取消或磁盘不足时留下的不完整数组不会被读。
- **生成前**：按通道数和尺寸估算所需磁盘，可用空间不足就不生成，日志写明。不新增界面。
- **已有项目**：新离线补建脚本 `scripts/build_corrected_display.py`。
  - 只读打开校正结果，绝不写它的属性：不继承旧脚本的 `--stamp-product`；
  - 校正结果没有 `source_identity` 的通道跳过；
  - 写进真实项目目录必须 `--in-place` 加用户对该项目的明确同意；`--out` 也不能绕过这一点：写到项目以外的目录可以，但程序不会读它。
  - 用户的 TMA4：先在 R6 的项目副本上做和测，真实项目要用户另外点头。

**B2.4 过渡层请求（改请求集合，本计划申请用户批准）**
- 现在：只请求最粗层和目标层；中间层只有之前读过、恰好保留时才画。
- **资格**：只对"所选 stride 的 display 数组通过校验"的校正通道生效。
  - Python 解析 display 层时逐个 stride 校验（身份、完成标记、形状、块原点、dtype），把通过的 stride 列表随清单传给 Rust（`py/corrected.rs`、`corrected.rs` 的 `Plane`）；
  - Rust 只认清单里的 stride，不检查目录存在与否，避免触发昂贵的全分辨率现场缩小。
- **选哪一层**：
  - 目标 = admission 实际选定的层（受预算批准的层，不是理想层）；
  - 过渡层 = 目标层再粗两级（例如全分辨率 → stride 4），而且这个 stride 必须在资格列表里；
  - 以下情况不请求过渡层：过渡层等于或粗于最粗层（和最粗层重复）、`coarse_only`、`base_overflow`、该通道最粗层还没到齐（`drawn()` 现有规则：最粗层不全时什么都不画，过渡层先读完也不会显示，所以不提前请求）。
- **请求顺序**（`viewer.rs` `issue()`）：
  1. 最粗层（不变）；
  2. 过渡层图块，按到画面中心的距离排；
  3. 目标层图块，按距离排（不变）。
  - legacy 排序分支同样把过渡层放在目标层之前。
  - **最粗层由缓存命中收齐时也要发出过渡层请求**：现在 `issue()` 先算好请求列表、再交付缓存命中，最后一个最粗块命中后重新规划出来的过渡层请求，不在已算好的列表里（异步收齐时 `frame.rs` 会再调一次 `issue()`，同步命中没有）。在 `issue()` 里闭合：交付命中后，如果有通道因此收齐最粗层，就在同一次调用里再取一次请求并发出，不需要等下一次用户操作。
- **预算（carry）**：
  - 过渡层和现有保留的顶替图块一起受 `carry` 限制：请求前先算"现有保留顶替块的字节 + 待要的过渡块字节"，超过 `carry` 就按离中心由远到近少要过渡块，`carry` 为零时不要；
  - 到达时（`deliver()`）再检查一次：超出 `carry` 的过渡块不收；
  - 不占用目标层已获准的容量。
- **退出**：
  - 现有 `drawn()` 只剔除比目标更细的旧块，不会剔除比目标粗的过渡块，所以加一条明确规则：一个过渡图块和当前 admission 目标集合（`a.tiles`）相交的那些目标格子都已经在 GPU 上时，这个过渡图块不再画，并从规划器的保留里释放。屏外、不在目标集合里的格子不算，否则边缘的过渡块永远退不出；
  - 判断依据是"目标图块在 GPU 上"（`on_gpu`），不是"线程读完"或"已送到 CPU"。
  - 相机移开后，过渡块和其他顶替块一样按现有 `retain()` 规则处理。
- **取消**：沿用现有的视图 epoch、`wanted` 替换和读取线程取消检查，不新增机制。
- 原图通道不变。Python 路径（后备）只认 16 位多层数据，不加过渡层请求；两条路径的差别写进说明。
- 关闭开关：`BLOCK01_STEP1_BRIDGE_LEVEL=0`。

**B2 文件白名单**
- Rust：`zarr_v2.rs`（`<u2`）、`corrected.rs`、`step1_tile.rs`（按 stride 取 display 层）、`plan.rs` 和 `plan/draw.rs`（过渡层的选择、carry、退出，加新小模块 `plan/bridge.rs` ≤ 约 200 行）、`viewer.rs`（只限资格传递、`issue()` 的请求排序，以及"缓存命中收齐最粗层后，在同一次 `issue()` 里重新取请求并发出"）、`py/corrected.rs`（清单传入）。

## 2. 验收（R6 的尺子，参数冻结）
**场景**
- 用户真实项目副本，冷读 S1（2500 像素/秒）和 S2，两档倍数，每种 3 轮；预热重放作参考。
- 参考图：
  - B1：停稳画面必须逐像素不变（回归验证），继续用 R6 的真实项目参考图。
  - B2：两档倍数下停稳画面用的是全分辨率图块，数据没变，所以应逐像素不变，继续用 R6 参考图；先验证这一点。
  - 如果有差异，先报告相对旧路径的差异和原因，再决定评分参考图；不靠重拍参考图把差异消掉。

**目标**（两档倍数分别达到，按 3 轮中位数）
- S2 拖动中糊的面积 ≤ 2%（R6：17.8% / 8–15%）；
- S1 拖动中糊的面积 ≤ 0.5%（R6：2.4% / 1.1%）；
- 跳转后画面到位 100 ms 以后，不再有"一半以上面积不合格"的帧（R6 最差一帧 99.6%）；
- 跟手、卡顿不比 R6 差（落后手增加不超过 1 帧的距离，卡顿合计增加不超过 20%）。
- 最后请用户人工验收"无感"。
- 达不到就如实报告，再定下一步。

**回归**
- B1：
  - OME-TIFF 冷读不比 R6 差；
  - 停稳画面逐像素不变；
  - 混合通道（原图 + 校正）项目；
  - 窗口关闭、来源重绑、缓存满时的公开路径行为；
  - Step3 标签读取若用到改过的 blosc 代码，也要回归。
- B2：
  - 逐层：源值误差 ≤ 0.5、有效区域一致；
  - 非对齐 ROI、奇数尺寸、舍入边界；
  - 缺失、过期、未完成、dtype 不符的 sidecar 都退回原路径；
  - Python 和 Rust 两条路径数值、有效区域一致；
  - 合成项目上确认分割和分析仍读原浮点产品；
  - 资格检查不通过的通道照旧显示。
- **过渡层专项**（合成项目和单元测试）：
  - carry 为零、或已被旧顶替块占满时不请求；
  - admission 降级（目标层变粗）时过渡层跟着变；
  - 过渡 stride 不在资格列表里时不请求；
  - 最粗层还没到齐时不请求；
  - 快速移动后迟到的过渡块按 epoch 规则丢弃；
  - 目标图块逐块上传时，过渡块按覆盖关系逐步退出；
  - 取消勾选通道、关闭窗口时没有残留请求和等待；
  - 最粗层由缓存命中收齐、目标未命中、之后不再操作：过渡层请求照样发出。

**每一步都报告**
- 糊的面积、最差一帧、跳变、新边缘变清楚时间；
- 排队和单块读取时间；
- 归因分布；
- 峰值内存和磁盘占用的实测值（替换 §1 里的估计值）。
