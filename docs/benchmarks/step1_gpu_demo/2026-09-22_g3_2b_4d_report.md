## 二、改动本身

1. `build_step1_stack(..., *, load_overview=True)`：`False` 时**只**跳过
   `controller.load_overview()` 一行，`setRange` 及其余一切不变。**默认仍是 True**。
2. `Step1WholeSlideMount.__init__`：`self._gpu_wanted` 为真时，把 host 既有的
   `stack_factory` **包一层**（`kwargs.setdefault("load_overview", False)`）。
   工厂签名不认识该关键字时**原样不动**（`_takes_load_overview` 做签名内省）。
3. 三个 CPU 回退点在 `_start_cpu_backend()` **之前**同步补读：
   `open()`、`_gpu_source_changed()`、以及 `source_changed()` 的 CPU 分支。
4. 无新增缓存 / scheduler / 线程池 / 队列 / timer / 生命周期状态机。

### 两处偏离「批准形状」，如实列出，等待用户接受或否决

- **`Step1ViewerHost.stack_factory` 读写属性。** 产品在
  `Step1ViewerBinding.__init__`（**不在白名单内**）里构造 host，mount 无法在构造时传工厂；
  备选是直接写 `host._stack_factory` 私有属性。该属性只是把**本来就是注入点**的东西读回来。
- **`source_changed()` CPU 分支的第三个补读点。** 一个 `gpu=True` 但 layer 在 open 阶段
  就失败的 mount，其 `gpu_binding`/`gpu_layer` 均为 None，因此 `source_changed()`
  **不会**走 `_gpu_source_changed()`，会经由仍被包装的工厂重建而永久
  `_blocked_on_overview`。变异 C 删掉它即有门转红。
