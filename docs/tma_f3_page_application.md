## 1. 编号：三种方式，全由用户指定顺序（9 月规范"对应到图像 core 的方法"）
程序负责选取、排序、预览和数量核对，不猜方向，也不猜编号。三种方式都不依赖片子摆向、表的大小或打孔顺序。

### 1.1 目标记录序列（三种方式共用）
- 每次编号前，用户先指定"这一段对应表上的哪些记录"，两种指定法：
  - **起止 + 顺序**：选起始位置和终止位置（如 X1-Y01 到 X1-Y19），再选顺序：
    - 沿列（X 不变、Y 递增）；
    - 沿行（Y 不变、X 递增）；
    - 以上两种的反向。
    起止之间按该顺序取记录。
  - **自定义**：在核心表里按住 Ctrl 依次点选记录，点的顺序即目标顺序。
- 目标条数 M 由上面的指定直接算出，与图上选中多少个无关。
- 目标序列取表上所有非空位置，样本和对照（如 Tonsil、肝 / 肾）都算；**表上的空位自动跳过，不当作核心**（9 月规范："empty 位置不自动匹配"）。
- 表上有样本、但图上缺失的位置不会自动跳过：用户分两段画，绕过这个位置（9 月规范的 A04 例子）。被绕过的记录保持"未对应"，由用户确认为"缺失"。
- 不靠"编号加一"来凑 ID。预览里逐项列出"图上第 k 个 → 位置 → 供体"。

### 1.2 分段拖线
- 用户从一个核心拖到另一个核心，沿行、沿列、斜着拖都可以。线两侧显示半透明的选取带，宽度用鼠标滚轮调，默认半个核心直径。
- 圆心落在选取带内的核心（含未归属的候选）按在线上的投影位置排序。
- 预览时可以：点一个核心移除或补选；点"反转"把顺序倒过来。
- 左栏显示"选中 N 个 / 目标 M 条"。**N ≠ M 时不能确认**；N = M 时仍要用户点"确认"。

### 1.3 连续点击
- 按点击顺序把核心排成一串，适合弯曲、错位的排列。
- Backspace 撤销上一点，Enter 结束。之后与 §1.1 的目标序列绑定，预览和确认的规则同上。

### 1.4 单颗编号
选中一个核心，在左栏搜索框里输入位置或供体，选一条记录：
- 选好后，左栏预览"该核心 → 位置 → 供体"，点"确认"才绑定。
- 记录已被另一个核心占用：预览中标红，可选"交换 / 改绑 / 取消"。改绑后，原来那个核心变为"未对应"，外形保留。
- 输入的编号不在表上：可以保存为"自定义核心，信息待补充"。补全的办法是对它再做一次单颗编号，绑定到表上的有效记录。锁定前必须补全，或者标为不纳入。
- 改一个核心的编号，不会让其他核心重新编号。

### 1.5 冲突一律先预览、再明确改绑
不会被悄悄覆盖。拖线、连续点击、单颗编号确认前，预览里把两类冲突都标红并计数：
- 选中的核心已经有编号；
- 目标记录已经被另一个（未被选中的）核心占用。

有冲突时，"确认"按钮变为"确认并改绑 K 条"。改绑后，被挤掉的核心变为"未对应"，外形保留，可以撤销。

### 2.2 核心与碎块（"并"）
- 每个候选是一块组织。一个核心可以包含多块组织（9 月规范：同一核心可以有多个不相连的组织块）。
- 程序不自动并入。小块或孤立块显示为灰色虚线"未归属"。
- **并入**：先选中一个核心，再点"并入"，然后逐个点碎块；按 Esc 结束。碎块成为这个核心的一部分：
  - 外接框取所有块的总范围；
  - 掩膜取所有块的并集；
  - 这个核心的编号变为"待复核"（9 月规范：已对应的对象被合并或删除块后，对应关系进入待复核，不自动沿用）。用户点一下"确认编号"即恢复为已对应；待复核的核心不能锁定。
- **移出**：在核心上右键某一块选"移出"，这块回到"未归属"，核心同样变为"待复核"。
- 并入或移出会让这个核心的外形改变；已经锁定的版本不受影响。

### 2.3 其他编辑
- **选中**：点圈选中，表格同步选中这一行；点表格某一行，缩略图居中到这个核心并加粗。
- **移动 / 改大小**：拖块移动，拖 8 个点之一改半径（保持圆形）。圈有重叠时，点击选中圆心离点击处最近的那个。
- **补画圈**：在组织上点圆心、拖出半径，得到一个新的"未对应"块。
- **不纳入**（软删除）：用于误检的候选，原因记下，可以恢复。
- **排除**：用于真实存在、但不分析的核心，保留位置、身份和原因。
- **确认缺失**：表上有样本、图上找不到时使用。缺失不等于空位。
- Delete 键 = 对选中的候选"不纳入"；Esc 取消选择或结束当前工具。
- Ctrl+Z 撤销、Ctrl+Shift+Z 重做。编号确认、拖动、并入、移出、补画、不纳入、排除，每次各算一步。
- **上一个 / 下一个**：按位置号走到相邻核心，缩略图居中放大。
- **在 Step1 看大图**：按以下顺序进行：
  1. 走 Step1 现有的入口检查（`_go_to_step1`，`main_window.py:4894`）。这个函数可能安排重试后立即返回（`:4921`），所以要等 Step1 真正进入、看图已挂上，最多等 10 秒；
  2. 再切到 Step1 的 `Viewer` 标签；
  3. 调用 `Step1WholeSlideMount.show_patch(核心外接框)`。
  
  入口检查不通过、超时，或 Step1 打开的不是同一张片子时，只给提示，不切换。
- **跑（勾选列）**：F4 用的核心选择，本段只保存。
- **版本**（标题栏下拉）：列出草稿和 v1…vn。
  - 锁定版本打开为只读，"锁定"按钮变成"基于此版修改"。
  - 重开页面时，有草稿就先打开草稿；只有用户点"放弃草稿"才删除。

### 2.4 状态分开记（9 月规范：表上的用途、图上看到的情况、质控三者分开）
每个位置存四个互相独立的字段，表格里的"状态"列由它们组合显示：
- **表上用途**（来自对应表）：样本 / 对照 / 空位。
- **对应**（来自编号操作）：已对应 / 未对应 / 待复核。
- **图上所见**（用户确认）：有组织 / 确认缺失。"多出来"的组织不挂在位置上，记在候选块上（未归属）。
- **质控**（用户确认）：未审 / 接受 / 排除（附原因，可多选）。

这样可以表达"已对应、有组织、但被排除"这类组合。

每个候选块（图上找到的每块组织）存一个归属：属于某核心 / 未归属 / 不纳入（附原因）。

全部由用户操作或对应表决定，程序不自己判断。

## 3. 锁定写什么
### 3.1 为什么不在 F3 写 `roi_config.json`（第二版第 4 点的通俗说明）
- 现有流程（Step0 的区域、Step1 融合、Step2 分割、Step4 定量）都从工作区里的 `roi_config.json` 读"要处理哪些区域"。现在它们默认这里只有一个区域。
- 如果 F3 锁定时就把 150 个核心写进去，打开 Step0 或 Step1 就会按"一个区域"的老规则去读 150 个区域：可能报错、卡住，或者全部去处理。
- F4 正好要改这件事：让流程认识多区域，并且只跑勾选的核心。所以由 F4 来写这个文件。
- F3 只把锁定结果完整存在 TMA 自己的文件里（下面两项），连每个核心的确切外形和区域编号都存好。F4 直接拿来写，不用重新计算。

### 3.2 锁定前检查（9 月规范"校验与锁定"）
不满足时列出原因，不锁：
- 每个非空位置：要么已对应且有组织，要么确认缺失；质控为排除的，也必须先满足其中一种；
- 没有"待复核"的核心；
- 每个候选块：属于某核心或不纳入；
- 没有一个核心对应两个位置，也没有两个核心对应同一位置；
- 不同核心**实际写出的区域**（§3.3 的外形，含多块之间的细缝）互不重叠，外接框允许重叠（9 月规范）；
- 没有未补全信息的自定义核心；
- 被勾选为"跑"的核心都已对应、未排除。

### 3.3 写入的文件
- **`tma/tma_cores_v<n>.parquet`**（n 从 1 起，只增不覆盖；沿用 F1 的表结构）：
  - 每个位置一行；
  - `status` 填 §2.4 四个字段组合成的显示文字，只供浏览；四个字段本身存在锁定记录里，以锁定记录为准；
  - 已对应的行填 `region_id` 和 `geometry`（JSON：各块的圆心与半径、`bbox_fullres = [y0, y1, x0, x1]`、`polygon_fullres`）；
  - 缺失、空位、排除的行没有区域。
- **外形规则**：
  - 每块圆用 64 边形近似，从正右方开始逆时针，取整到整数像素并裁剪到片子范围内；
  - 现有 `region_id`（`project_identity.py:236`）和现有掩膜读取（`core/preseg_input.py:83` `RoiMask`，用 `cv2.fillPoly` 填一个多边形）都只认一个多边形。因此区域的 `polygon_fullres` 这样定：
    - 单块核心：就是这块的 64 边形。
    - 多块核心分两步：
      1. 先合并重叠的块：在原图分辨率下，把各块圆（64 边形）画到这个核心外框大小的画布上，取并集，再取外轮廓（`cv2.findContours`，只取最外层）。互相重叠或相切的块因此变成一个轮廓，不会出现奇偶填充把重叠处挖空的问题；轮廓内的空洞一并填上，因为区域只表示归属。
      2. 只剩一个轮廓时，直接用它。还有几个互不相连的轮廓时，用一来一回的细缝把它们连成**一条轮廓**（"钥匙孔"连法）：连接顺序取最短连线（最小生成树），每条细缝连在两轮廓最近的两个顶点之间；整体从左上方的轮廓开始，顺序固定。
    - 不用凸包，因为凸包会把块之间的玻璃甚至邻近的核心也包进来。
    - **锁定检查用实际写出的区域**：每个核心的区域按 `RoiMask` 同样的方法填出来，细缝线也算在内；两个外框相交的核心，填出来的像素不能有重叠。细缝穿过邻近核心就会被检查拦下，提示用户移动块或把块移出。
    - 规范化后的外形（取整、`normalize_polygon` 之后）一变，`region_id` 就变，符合总方案 §3"几何一改即新 ID"。小于 1 像素、取整后看不出来的微调不算外形改变，ID 不变。
    - 轮廓坐标：画布内的整数坐标直接加上外框左上角 (x0, y0)，不加 0.5 像素偏移。
    - 实现第一步先用测试核对 `RoiMask` 的填充结果，覆盖以下情况：块分开、重叠、一块包含另一块、相切、三个以上互不相连的轮廓（细缝有分叉，连接顺序和并列时的取舍固定可重复）、被片子边缘裁掉后退化（规范化结果为空时明确拒绝锁定并说明原因）、细缝穿过邻近核心；同时核对 `normalize_polygon` 的转向和起点变化不改变填充结果。任何一项不通过就停下报告，不改 `RoiMask` 和 `region_id`。
  - `bbox_fullres` 由 `polygon_fullres` 的整数顶点得出：下界取最小值，上界取最大值 + 1（半开区间，边界像素不会被裁掉），再裁剪到片子范围内。
  - `region_id = project_identity.region_id(slide_id, "TMA_core", bbox_fullres, polygon_fullres)`，不改这个函数。
- **`tma/tma_layout_v<n>.json`（锁定记录）**：
  - `slide_id`；对应表的文件指纹和解析快照（引用 F1 研究记录）；
  - 所用候选列表的版本；
  - 每个核心的内部编号 `core_uid`（改编号时不变）及其所含块；位置（用 F1 的 `position_key` 作为稳定的记录键）→ 样本 → 外形 → `region_id`；
  - 每个位置的四个状态字段（§2.4）；
  - 坐标约定：原图 level-0 像素，左上角为原点，x 向右，y 向下；外框按 A3 写成 `[y0, y1, x0, x1]`，半开区间（与 9 月规范的 `[x0, y0, x1, y1)` 是同一个框，只是写法不同）；
  - 用户勾选"覆盖范围已核对"及时间；
  - 每次编号操作：方式（拖线 / 点击 / 单颗）、本段有序的核心与目标记录、线段与选取带宽度、确认时间；
  - 碎块的归属；不纳入、排除和缺失的原因；
  - 勾选的核心；本版号和所基于的版本。
  - 登记来源记录，新类型 `tma_layout`，依赖对应表和候选列表两项。
- **`tma/tma_layout_draft.json`**：每次编辑后自动保存，不登记。
