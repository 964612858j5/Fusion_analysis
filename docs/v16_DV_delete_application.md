# v16 DV-D 申请 v1：在 Load 的选择框里删除（放进垃圾桶，30 天后清除）

状态：**v1，已批准**（2026-10-03，用户「同意一起跑全量回归，批准你开工」）。属于数据版本块（`docs/v16_data_versions_application.md`）的补充。

修订记录：v0 草稿（按「工作区 + 版本」删）；v1 写入用户的两轮裁定和 codex（gpt-6-astra，low）的意见：删除的单位改为「数据版本 + 分割运行」的组合；数据版本、工作区是否一起删，每次都问用户；当前版本可以删；「None」让界面回到初始状态。

## 1. 为什么要做

每次 Generate 成功都会多一个数据版本，每次 Step2 都会多一个分割运行。数据版本至少有一组 fused（test1 的 Full WSI 几百 MB），改了校正参数的还多一份完整的 corrected（约 221 MB）。不删的话，只增不减。

## 2. 删除的单位：「数据版本 + 分割运行」的组合

- 每次分割运行只属于一个数据版本（`segmentation_meta.json` 的 `data_version`）；一个数据版本可以有多次分割运行。
- 所以一个「组合」就是**一次分割运行**加上它所属的数据版本。删除一个组合，**只删这一次分割运行**（连同它的 Step4 定量结果），不删同一个数据版本的其他分割运行，也不删别的数据版本。

Load 之后的「Open a workspace」选择框，每行改为一个组合：

| 行 | 例子 | 点这一行 |
|---|---|---|
| `draft` | 还没 Generate 的修改（已做完） | 接着做 draft |
| 组合行 | `v002 · stardist · 10-03 12:00` | 加载 v002，Step3 里选中这次分割 |
| 未分割的数据版本 | `v002（未分割）` | 加载 v002 |
| 没有版本记录的工作区 | `unknown` | 和今天一样打开工作区 |

版本号仍然右对齐在行尾。行首加 **×**。

## 3. 点 × 之后（用户裁定）

**3.1 组合行**
1. 确认框列出要删的全部内容，例如：「删除 `v002 · stardist · 10-03 12:00`：分割结果（xx MB）和它的 2 个 Step4 定量结果」。
2. 如果这是 v002 的**最后一次**分割运行，确认框里再问一句：**「也删除数据版本 v002 吗？」**
   - 选「删除」：v002 一起进垃圾桶（它的 fused、参数副本；corrected 只在没有其他版本或 draft 引用时才挪走）。框里写明：「以后要用这套参数，需要重新 Generate」。
   - 选「保留」（默认）：只删这次分割；v002 留下，变成 `v002（未分割）` 一行，下次加载后可以接着分割。

**3.2 未分割的数据版本行**：确认后删除这个数据版本。

**3.3 `draft` 行**：确认后放弃还没 Generate 的修改。工作区的 Step0 / Step1 文件回到当前版本的样子；只属于 draft 的 corrected 草稿进垃圾桶。

**3.4 删除的是当前版本时**（3.1 选了连数据版本一起删，或 3.2）
1. 先问：**「要加载另一个版本吗？」** 下面是一个下拉框，列出这个工作区剩下的版本（要删的不在里面），**默认选「None」**。
2. 选了某个版本：先加载它（加载成功才继续；失败就什么都不删），再删除原来的当前版本。
3. 选「None」：删除，然后整个界面回到**刚启动时的样子**：没有通道、没有图像，等你自己 ▶ Load。

**3.5 删除的是这个工作区的最后一个数据版本时**：再问一句：**「这个工作区已经没有数据版本了，要删除整个工作区吗？」**
- 删除：整个工作区文件夹进垃圾桶。
- 保留（默认）：工作区留下（里面可能还有 draft，或者没有版本记录的旧分割），它的 Step0 交接清掉（交接原来指向的产品已经进了垃圾桶），在选择框里显示为 `unknown`。

## 4. 不能删的时候

- 这个组合里的任何东西正被 Step2 或 Step4 使用（包括批量任务），或者 Step0 Save、Generate 正在进行：拒绝，并说明原因；**等运行结束才能删**。
- 正在 Step3 或 Step4 里打开、但没有运行的分割：先断开（Step3 换到别的运行或清空，Step4 清掉选择），再挪文件，最后刷新列表。
- corrected 产品是不是「没人用了」，按**剩下的所有版本和 draft 的引用**判断，不按它放在哪个文件夹判断。

## 5. 垃圾桶

- 位置：`<项目>/.trash/<删除时间>_<工作区 id>_<内容>/`，保持原来的相对路径，另有 `trash.json`：原路径、删除时间、大小、删了什么。程序找工作区、版本、分割运行时不会看这个文件夹。
- 和项目在同一个磁盘上：挪进垃圾桶是改名，几乎不花时间，也不占额外空间。
- **30 天从删除那一刻算**；每次 ▶ Load 这个项目时检查，删除时间超过 30 天的条目永久删除（后台进行，终端打印删了什么）。
- 选择框底部「Empty trash…（xx GB）」：确认后清空这个项目的垃圾桶。
- **不做「从垃圾桶恢复」的界面**。需要时手动挪回；`trash.json` 写了原路径，但手动挪回不会修复 `index.json`，这一点写进用户指南。

## 6. 删除中途失败

一次删除要挪好几个文件夹、改 `index.json`，不是一步完成的。顺序：
1. 先在 `.trash/` 里写 `trash.json`，标记「进行中」；
2. 先改 `index.json`，把要删的版本去掉（这一步之后，它对程序来说已经不存在）；
3. 再挪文件夹；
4. 最后把 `trash.json` 标记为「完成」。

中途失败（例如断电），下次 Load 时：`trash.json` 还是「进行中」的条目，把还没挪的文件夹继续挪完。不会留下「index 里还有、文件却在垃圾桶里」的版本。30 天清除只清「完成」的条目。

## 7. 记录（A3）

A3 只追加、不改写。每次删除追加一条记录：删的是哪个分割运行、哪个数据版本、哪个工作区，挪到了哪里，什么时间。只删分割运行时，记录里不会写「删除了数据版本」。不新造任何哈希。

## 10. 验收

**自动（每条都做反向注入）**
- 删一个组合（数据版本还有别的分割）：只有这次分割和它的 Step4 结果进垃圾桶；数据版本、其他分割一个字节都没变。
- 删最后一个组合，选「保留数据版本」：数据版本留下，选择框里出现 `vNNN（未分割）`；选「删除」：数据版本一起进垃圾桶，共用的 corrected 不动。
- 删当前版本，选另一个版本：先加载成功再删；加载失败什么都不删。选「None」：界面回到初始状态，晚到的结果不会重新填上，之后 ▶ Load 正常。
- 删最后一个数据版本：选「保留工作区」，工作区变 `unknown`；选「删除」，整个工作区进垃圾桶。
- Step2 / Step4 正在使用时拒绝；取消确认时什么都不变。
- 中途失败：模拟挪到一半失败，下次 Load 时续做完成，index 里没有指向垃圾桶的版本。
- 30 天：`trash.json` 的时间改成 31 天前，Load 后被永久删除，29 天前的还在；Empty trash 清空全部。
- A3 里有对应的删除记录。

**真机**：在 test1 的验收副本上做两个数据版本、各分割两次，按第 3 节逐种删除，看选择框、Step3 下拉框、`.trash/` 和界面。
