## 2. `stride == 1` 快路径的准确行为

`stride == 1` 不是归约：一个 1×1 的格子就是那个像素本身。旧实现仍然为每个
像素造一个 block index，再用 `np.add.at` 把它散射进输出去除以 1。

新行为（`reduce_corrected()` 内的早返回，**不在 `read_tile()` 里另造一套 ROI
裁切**）：

1. 先问 `region.overlaps(rect)`。**完全在 region 外时一次 `region.read()` 都
   不发**，因此不读盘；返回全 0 的 `values` 与全 `False` 的 `valid`。
2. 有交集时只发**一次** `region.read(y0, y1, x0, x1)`。
3. 按 `region` 返回的 `placed` 坐标，以及**实际返回数组的形状**（不是请求的
   矩形），把像素放回输出的对应位置；该范围 `valid=True`，其余保持
   `values=0 / valid=False`。`placed` 比请求交集小的防御情形因此不会凭空
   造出像素。
4. 返回 shape 与请求矩形**完全一致**，`values` 为 `float32`、`valid` 为
   `bool`。
5. 数值 0 是**样本**（`valid=True`），不是缺失；NaN/Inf 原样透传，其所在位置
   仍然 `valid=True`。
6. 仅当 `(y1-y0)*(x1-x0) <= max_elements` 时走快路径。超过预算的矩形退回下面
   的有界步进，结果不变、读取仍受限（门：
   `test_a_stride_one_rectangle_over_the_budget_still_stays_bounded`）。

**快路径的可观测签名：** 一块装得下的瓦片只发 **1 次** `region.read()`；
有界步进会把同一矩形切成多块小于预算的 slab。门
`test_a_stride_one_tile_is_read_once_rather_than_walked` 与
`test_a_fine_corrected_tile_is_copied_rather_than_reduced` 就是用读取次数把
两条路径区分开的（变异 M1 因此转红）。

## 3. `stride > 1` 的算法与全局网格相位

### 3.1 网格仍然锚定在 level-0 原点

旧实现的 block index 是 `(r - y0 + y0 % stride) // stride`。令
`a = y0 - y0 % stride = stride * (y0 // stride)`，它是 `stride` 的整数倍，于是

```
block(r) = (r - a) // stride = r // stride - y0 // stride
```

**新实现直接用这个等价式**：`base_by = y0 // stride`，一个 level-0 行 `r` 属于
输出块 `r // stride - base_by`。相位因此由 level-0 原点决定，与请求矩形起点、
ROI 起点、slab 切法都无关。输出高度 `ceil(y1/stride) - y0//stride`，与旧式
`ceil((y0%stride + (y1-y0))/stride)` 恒等。

### 3.2 每个 slab 怎么求和

对每个读回来的 slab：

1. 相位取自 **`placed` 的实际起点**（不是走位游标）：
   `front_y = sy0 % stride`、`front_x = sx0 % stride`。
2. 把 slab 补齐到全局网格的整块：前面补 `front`、后面补
   `pad = (-(front + 长度)) % stride`。**补的是 0，对求和没有贡献。**
3. `values.reshape(bh, stride, bw, stride).sum(axis=(1, 3), dtype=np.float64)`
   ——沿两个 block 轴一次求和，累加器仍是 `float64`，与旧实现相同。
4. 落位 `oy = sy0 // stride - base_by`、`ox = sx0 // stride - base_bx`。

**没有任何一个 level-0 像素被单独散射。**

### 3.3 边块怎么归一（这是最容易写错的一条）

补出来的 0 绝不能进分母，否则 ROI 边缘会被拉黑。计数**不用掩码数组**，而是
两个小向量的外积：

```
rows_in[i] = |[i*stride, (i+1)*stride) ∩ [front_y, front_y + h)|
cols_in[j] = 同理
counts[i, j] += rows_in[i] * cols_in[j]
```

即 `_span_per_block()`。于是边块**按它实际拿到的样本数**归一，跨 ROI 边界的
部分块保持原亮度（门
`test_the_region_edge_is_divided_by_the_samples_it_really_got`，变异 M3 转红）。
`valid = counts > 0`：ROI 外不计数、不显示；**数值 0 仍然计数、仍然 valid**
（变异 M7 转红）。

### 3.4 走位切法

游标按 **block 边界**步进：`stop = min(o1, (cursor // stride) * stride + rows)`，
`rows`/`band` 都是 `stride` 的整数倍。因此一个轴上**只有第一块和最后一块**
可能落在网格外，中间全部天然对齐、连 `np.pad` 都不用调。

切法不影响结果：门
`test_how_the_walk_is_cut_does_not_change_the_answer` 用
`max_elements ∈ {64, 1024, 9999, 250000, 4Mi}` 比对同一答案；
`test_a_world_block_reads_the_same_from_every_tile_that_covers_it` 用同一个
世界块在 `stride` 种不同相位的矩形里读取，要求差 ≤1e-4。变异 M2、M5、M8
均转红。

## 4. 最大单次读取与临时数组规模

预算 `MAX_REDUCTION_ELEMENTS = 4 194 304` **未提高**（门
`test_the_reduction_budget_has_not_been_raised`）。

`_slab_geometry()` 把预算花在 **`(rows + stride) × (band + stride)`** 上而不是
`rows × band`——因为 slab 补齐最多各加一个块，**如果只约束读取，超预算的会是
临时数组，而产物侧的门永远看不见它**：

| 1 | 2047 | 2047 | 4 190 209 | 4 194 304 | ✅ |
| 2 | 2046 | 2046 | 4 186 116 | 4 194 304 | ✅ |
| 3 | 2046 | 2043 | 4 179 978 | 4 192 254 | ✅ |
| 4 | 2044 | 2044 | 4 177 936 | 4 194 304 | ✅ |
| 7 | 2044 | 2037 | 4 163 628 | 4 192 244 | ✅ |

两侧都有门：产物侧 `_HugeProduct` 在任何一次读取超过预算时立即

## 6. 非对齐 ROI / rect / chunk 的证据

上面的参数化本身就是这条证据：

- **ROI 起点非对齐：** `(5,3)`、`(101,97)` 对 `stride ∈ {2,3,4,7,16,64}` 全部
  不整除；§3.3 的边缘测试刻意把 region 起点放在 `stride+2, stride+3`。
- **请求起点非对齐：** 六个起点里包含 `ry+1`、`rx+2` 等。
- **宽高小于 stride、且不是 stride 整数倍：** 尺寸集合含 `(1,1)`、
  `(stride+1, stride-1)`、`(2*stride+3, 3*stride+2)`、`(40,46)`；另有
  `test_a_rectangle_smaller_than_one_block_is_still_right` 逐相位扫描。
- **chunk 边界：** 真实产物 chunk 为 `1024×1024`，slab 为 `1984×1984`，两者
  互不对齐，而 §5.1 的结果逐位相同。合成侧由
  `test_how_the_walk_is_cut_does_not_change_the_answer` 用五种 `max_elements`
  覆盖。
- **同一世界块的接缝：** `test_a_world_block_reads_the_same_from_every_tile_that_covers_it`
  对 `stride ∈ {4,7,16}` 各取 `stride × 3` 个不同相位的矩形。
