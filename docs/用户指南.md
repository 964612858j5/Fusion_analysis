# Block01 用户指南 — CODEX 多通道组织影像分析流水线

> 这份文档写给**第一次接触这个软件的人**。哪怕你没学过生物或编程，照着一步步做也能跑通。
> 看到 `<!-- 图片占位 -->` 的地方，是需要补一张截图的位置，图片放进 `docs/images/` 文件夹即可。

---

## 一、这个软件是做什么的？（先看懂目的）

想象你有一张**超大的组织切片照片**（一块肿瘤或一片皮肤的显微图）。
这张照片不是普通照片，它同时用了大约 **十几到几十种"染料"**，每种染料只点亮一类东西：

- 有的染料只让**细胞核**发光（比如 DAPI）；
- 有的只让**免疫细胞**发光（比如 CD3、CD8、CD68）；
- 有的只让**上皮细胞**或**血管**发光（比如 CK19、CD31）。

每一种染料 = 一个**通道（channel）**。一张图叠了几十个通道，文件可能有几十 GB 那么大。

**我们的目标，用一句话说：**

> 把这张巨大的多通道照片，变成一张**Excel 表格**——
> 表格的每一行是**一个细胞**，每一列是**这个细胞在某个通道上的亮度**。

有了这张表，科学家就能回答："这块组织里有多少免疫细胞？它们离肿瘤细胞有多近？" 等问题。

这就像在一张万人合照里，**先把每个人圈出来，再记录每个人穿什么颜色的衣服**——只不过这里的"人"是细胞，"衣服颜色"是各个通道的亮度。

## 二、整体流程（5 个步骤，按顺序走）

软件把整件事拆成 **5 步**，顶部有一排步骤导航，从左到右点着走就行：

```
Step 0          Step 1          Step 2          Step 3        Step 4
 设置      →     融合 + 调参  →   分割 + 合并  →   质检     →    特征提取
Setup          Fusion          Segment+Merge   QC Viewer     Feature
```

| 步骤 | 名字 | 一句话作用 | 产出 |
|------|------|-----------|------|
| **Step 0** | Setup 设置 | 选要分析的区域、整理通道、去背景噪声 | 校正后的图像、ROI 区域配置 |
| **Step 1** | Fusion 融合 + 调参 | 把多个通道合成一张"细胞轮廓图"，在小块上试出最好的分割参数 | 分割参数文件 |
| **Step 2** | Segmentation 分割 + 合并 | 用选好的参数，把**整个区域**的每个细胞都圈出来 | 全图细胞掩膜（mask） |
| **Step 3** | QC 质检 | 对照组织检查圈得准不准 | 确认/不确认 |
| **Step 4** | Feature 特征提取 | 量出每个细胞每个通道的数值，导出表格 | `cell_features.h5ad`（勾选时另有 CSV） |

> **核心思路**：前面的步骤都是"准备和试验"，真正吃力气的是 Step 2（处理整张大图），最后 Step 4 出表格。

## 三、安装与启动

### 1. 准备运行环境（只需做一次）

这个项目依赖 GPU（推荐 NVIDIA 显卡）和一套 Python 环境。环境定义在上一级目录的文件里：

- `environment.yml`（conda 环境，名字叫 `fusion`）
- 或 `setup_env.sh`（一键脚本，会建一个叫 `fusion_test2` 的环境）

第一次安装，在终端里运行（任选其一）：

```bash
# 方式 A：用现成的 environment.yml
conda env create -f /sda1/Fusion/analysis_pipline/environment.yml

# 方式 B：用一键脚本
bash /sda1/Fusion/analysis_pipline/setup_env.sh
```

> 如果你需要自己执行登录类命令或交互命令，可以在本会话输入框里用 `! 你的命令` 直接运行。

### 2. 启动软件

激活环境后，**进入项目上一级目录**，把 block01 当成一个 Python 模块来启动：

```bash
conda activate fusion          # 或 micromamba activate fusion_test2
cd /sda1/Fusion/analysis_pipline
python -m block01.main
```

启动成功后会弹出一个**深色主题的窗口**，标题是 `CODEX Pipeline | Fusion + Segmentation`，默认停在 Step 0。

<!-- 图片占位：images/02_启动后的主窗口.png —— 软件刚打开、停在 Step 0 的整体窗口截图 -->

### 3. 先改好配置（可选但推荐）

文件 `block01/config.py` 里有几个常用默认值，第一次用可以先填上自己的数据路径：

```python
OME_TIFF_FILE = ".../xxx.ome.tif"   # 你的原始多通道大图
OUTPUT_DIR    = ".../pipeline_v2"   # 结果输出文件夹
```

> 不改也行——软件界面里也能用"浏览/Browse"按钮选文件。

## 四、逐步使用说明

下面每一步都按 **「这一步在干嘛 → 怎么操作 → 注意事项」** 来讲。

---

### Step 0 · Setup（设置）

**这一步在干嘛？**
把原始大图读进来，**圈出你真正关心的区域（ROI）**，整理通道分组，并**去掉背景噪声**。相当于"拍照前先擦干净镜头、对准要拍的人"。

**怎么操作：**

1. **加载图像**：填好原始 `.ome.tif` 路径和输出目录，点加载，软件会显示一张**缩略全景图（overview）**。
2. **画 ROI**：在全景图上框出要分析的区域（可以画多个，命名 ROI_1、ROI_2…）。只处理 ROI 能**省下大量时间和内存**。
3. **设置通道分组与细胞核通道**：
   - 在 **Channels** 面板里给每个通道归类（上皮 / 免疫 / 血管…）并设权重；
   - 在 **Nucleus Channel** 里选细胞核通道（通常是 `DAPI`）。
4. **背景校正（去噪）**：在 **Method Parameters** 里选去背景方法：
   - **TopHat**：经典形态学去背景，半径可调；
   - **cucim**：GPU 高斯背景扣除，更快（需要显卡支持）。
   - 在 **Patch Preview — Original | TopHat | cucim** 面板里可以**并排对比**原图和两种去背景效果，挑出更干净的那个。
5. **选预览小块（Preview Patch）**：勾几个有代表性的小区域，后面 Step 1 调参就用这些小块快速试，不用每次跑整张图。
6. 点"处理/Process"，软件会生成校正后的图像和配置文件。

**产出：** `corrected_channels.zarr`（校正后图像）、`roi_config.json`、`patch_config.json`、`correction_config.json`、`step0_roi_result.json`。这些会被后面所有步骤自动读取。

> 💡 **小贴士**：背景校正是"宁可轻一点别过头"。扣得太狠会把真实信号也抹掉，让细胞变暗、分割变差。

---

### Step 1 · Fusion（融合）+ 分割调参

**这一步在干嘛？**
做两件事：

1. **融合（Fusion）**：把你在 Step 0 分好组的多个通道，**合并成一张"细胞质/轮廓图"**，再配上一张"细胞核图"。预览里 **红色=细胞质，蓝色=细胞核**，实时更新。
   - 道理很简单：单个通道往往只点亮一部分细胞，把它们叠加（取最大值）后，几乎每个细胞的边界都能被照亮，分割算法才看得清。
2. **调参（Grid Search）**：在 Step 0 选的**小块**上反复试，找出能把细胞圈得最准的**分割方法和参数**。

**怎么操作：**

1. 进入 Step 1 后点 **Load Step0 ROI Result**（通常会自动加载）。
2. 左边选预览小块，中间看融合预览，**调通道权重**直到细胞轮廓清楚。
3. 在右边 **Method & Parameters** 标签页里**选分割方法**（方法说明见下面"附录 A"）。
4. 用两段式搜索快速定参数：
   - **Phase 1 — Auto-diameter**：自动估计细胞直径（先试一组直径，看哪个最合适）；
   - **Phase 2 — Fine search**：在 `flow × cellprob` 两个参数上做网格细搜。
   - 结果会在 **Patch Results** 标签页里以表格/缩略图展示，点一下就能选用某组参数。
5. 满意后点底部 **💾 Save Config & Generate fused.zarr** 保存参数。

**产出：** 分割参数文件（`cellpose_params.json` 等）、`fused.zarr`、`step1_session.json`（下次可"Load Previous Step1 Session"接着调）。

> 💡 **为什么要先在小块上调？** 整张大图跑一次可能要几十分钟甚至几小时。先在指甲盖大小的小块上把参数试好，再去跑大图，省时省力。

---

### Step 2 · Segmentation & Merge（分割 + 合并）

**这一步在干嘛？**
拿 Step 1 调好的参数，**真正地把整个 ROI 的每一个细胞都圈出来**。因为整张图太大放不进显存，软件会**切成一格一格的小瓦片（tile）分别处理，再拼接（merge）成一整张全图掩膜**。

**怎么操作：** 参数在左边的 **Parameters** tab，瓦片概览和进度在右边的 **Tile Status** tab；**← Back to Step 1**、**▶ Run Segmentation & Merge**、**⏹ Stop** 在最下面一行。左栏与 Step 0 / 1 / 3 的通道列同宽，在任何一页拖动，所有页一起变。

1. 在 **Input Data** 里确认输入（融合图 / 参数文件，通常自动带过来）。可以点 **Load zarr info & overview** 看一下。
2. **Tile Grid**：设置瓦片大小（切多大一格）。瓦片越小越省显存，但接缝处要更小心。
3. **Segmentation Parameters**：确认参数；也可以 **Apply Selected Params** 套用之前选好的那组。
4. 选好 **Output** 输出位置，点 **▶ Run Segmentation & Merge** 开始。进度条会显示处理到第几格；**Tile Status** 里正在计算的格子是黄色，完成的是绿色。运行期间改 **Rows / Cols** 不会影响这次运行：新网格上不显示任何状态（那些格子对应的是图像的其他部分），改回这次运行的网格（显示在瓦片信息下面一行，`Running grid: …`）后，所有状态会重新显示。
5. 中途想停可以点 **⏹ Stop**；万一中断了，**Recovery Mode** 能从已保存的中间文件继续合并，不用从头再来。

**Step 1 之后引擎变了**（2026-09-29）：如果做 Step 1 结果之后，这个方法的分割行为或模型改变了，运行前会弹出 **Segmentation engine** 警告，列出变了什么——Step 1 的预览是按旧的方式做的，全图结果可能与预览不同。点 **Run anyway** 照常运行，并把这项差异记进结果；点 **Cancel** 不运行。没有变化时不会询问；本次更新之前的 Step 1 结果也不会询问（只做记录）。安装与分割无关的包不再算作变化。

**产出：** 全图掩膜 `global_mask`（一个超大的 uint32 数组 / OME-TIFF）。掩膜里每个对象有一个唯一编号（1、2、3…），背景是 0。整细胞方法和 expansion 方法里是细胞；纯核方法里是细胞核。

**同时算出核的方法也保留细胞核**（`Cellpose nuclei (DAPI) + expansion`、`StarDist nuclei + expansion`、`Mesmer nuclear-guided whole-cell`）：`global_nuclei_mask` 里是细胞核，每个核有自己的编号；`global_nuclei_cell` 记录每个核属于哪个细胞。只有完全落在一个细胞里的核才保留；一个细胞可以有多个核。终端和运行的 metadata 会报告预测了多少核、保留了多少、丢弃了多少（跨多个细胞、一部分在背景上、完全在细胞外）。本次更新之前的结果没有核文件——要重跑 Step 2 才会有。

**切块接缝**（Step 2 更新，2026-09-27）：每个切块带一条重叠带分割，所以靠近切块边界的细胞通常会被两个（角上最多四个）切块各预测一次。Step 2 现在把这些版本对上、只保留**一个**：共享像素达到较小那个版本一半以上的，算同一个细胞；更位于自己切块内部的那个版本胜出（一个切块看到一个细胞、另一个切块看到两个时，整组按胜出切块的版本保留——两个都留或都不留）。两边都会丢掉的细胞会被保留；在更好的邻居旁边只剩不到一半像素的细胞整个丢弃，不留碎片；不再完全位于自己细胞内的核丢弃（计为「on tile seams」）。现在每个细胞编号都有像素。以前的 Step 2 结果在接缝上是后面的切块覆盖前面的（细胞被截断、出现小碎片、核落在别的细胞里）——请重跑 Step 2。终端与运行的元数据（`seam_merge`、`seam_reconciliation`）给出这些计数。重叠带必须比最大的细胞宽（Step 1 的 halo，默认 200 px）。

**过大的对象**（Step 2 更新，2026-09-27）：比该方法在真实组织上分出的对象大得多的对象是预测伪影——例如 StarDist 在几乎全是背景的切块上可能给出一个覆盖整块的巨大多边形——Step 2 在合并之前把它丢掉（否则它会占掉真实细胞的像素）。上限是本次运行所来自的 Step 1 预分割里对象面积中位数的 50 倍（至少 10 000 px）；没有可用的 Step 1 结果（少于 20 个对象，或参数是手动设置的）时为 100 000 px。终端与运行的元数据（`size_filter`）给出上限、它的来源，以及丢掉了多少个对象（与它们的核，「in oversized objects」）。

### Step 3 · QC Viewer（质检）

**这一步做什么：**
对照组织检查 Step 2 的结果：整张图叠加细胞掩膜，可以拖动、缩放，用 Tissue Navigator 或 patch 空降。排版和用法与 Step 1 相同。

**怎么用：**

1. 左栏就是 Step 1 的 `Channels` 框：`Show all`、`Intensity…`、`Reset weights`、`Load weights`，以及带权重的通道列表。
2. **Step 3 和 Step 1 共用同一套通道、权重和 fusion**：在这里改的勾选或权重，回到 Step 1 是一样的（也会像 Step 1 的改动一样记进会话）。已保存的 Fusion Settings 只有在 Step 1 点保存时才会变。
3. `Overlay` / `Fusion` 同时切换 Step 1 和 Step 3 的模式；Tissue Navigator 跟随这里的设置。
4. 右侧显示**整张图**，和 Step 1 一样：拖动平移、滚轮缩放、在 Tissue Navigator 里点一下就空降过去。Step 0、Step 1、Step 3 之间切换时，显示的是切片上的同一位置、同样的缩放（2026-09-30）；这三页也使用同一套页面布局，所以图像、通道面板和 tab 在屏幕上完全不动。Step 0 的工作区有两个 tab：**Background Correction**（通道）和 **Viewer**；Per-Channel Decision 和 **Save** 在最下面一行。三页的通道列同宽；拉得很窄时，每一行最右边的部分（权重框，或 Step 0 的方法框）会被列的边缘遮住，拉宽就又能看到。在 Step 1 和 Step 3 里拖动窗口大小时缩放不变，只是看到的范围变大或变小。
5. 在 Step 3 的 Tissue Navigator 里，**ROI 是锁定的**（继承自 Step 0 / Step 1，这里不能画、不能删、不能改）；**patch 可以新增、拖动、改名和删除**，patch 的改动会保存，并同步到 Step 0 和 Step 1。
6. **patch**：图像上方一行的开头就是 Step 1 的 patch 按钮（`Patch ▾` 列出全部）。点一下，图像空降过去。选中的 patch 在 Step 1 和 Step 3 是同一个。
7. **整张图上叠加细胞掩膜。**
   - **运行**下拉框，在 `Viewer` 标签那一行的右侧：**这个项目在这张切片上历次会话**的 Step 2 结果（方法、日期和时间；本次会话的排在前面，当前生效的会标出来；之前会话的结果在 `[ ]` 里写明是哪次会话）。每个结果按它自己的区域显示。旁边的 **`Load…`** 可以打开别处（别的项目）的结果文件夹，只要是在这同一张切片上做的；否则提示文字会说明为什么没有载入。从 Step 2 完成对话框或 `Load…` 进来时显示那一次；否则显示你上次选的、本次会话当前生效的，或最新的一次。结果有一部分在当前 ROI 之外时，提示文字会说明——Step 3 只显示当前 ROI；
   - **`Cell mask ▾`** 和 **`Nucleus mask ▾`**：点开设置 `Show`（显示）、颜色（预设色或 `Custom…`）、`Opacity`（透明度）、`Width`（线宽 1–4）和 `Outline` / `Fill`（轮廓 / 填充）。所选颜色用于轮廓；`Fill` 给每个细胞一种固定颜色。这次运行没有某种掩膜时按钮变灰（例如纯核方法没有细胞掩膜、整细胞方法没有核掩膜；本次更新之前的 expansion 结果会提示重跑 Step 2）；
   - 同一行再往右是**提示**，说明掩膜为什么没显示，例如还没有 Step 2 结果、结果不属于这个 ROI（请重跑 Step 2）、`Masks need the GPU display`（需要 GPU 显示）、`Preparing zoomed-out masks…`（旧结果第一次打开时在准备缩小用的层级）、缩小时无法显示掩膜。鼠标悬停可以看全文。
   掩膜跟随拖动、缩放和每次空降。掩膜设置在程序运行期间保留；不往项目里写任何文件，只有旧结果第一次打开时会在它自己的运行目录里补上缩小用的层级。

**产出：** 没有新文件（旧的 Step 2 结果第一次打开时，在它的运行目录里补生成缩小用的掩膜层级）。

### Step 4 · Feature Extraction（特征提取）

**这一步在干嘛？**
到了**出表格**的时刻。Step 4 遍历一个 Step 2 结果里的每一个细胞，在**一遍扫描**里量出它**在每个通道的亮度**——全细胞，以及结果保留了核时它的**核**与**胞质**各自的亮度——**和它的形状**，存成一张可直接分析的表。

**数值从哪里来：** 每个通道按 Step 0 的决定读取——保持 `original` 的通道读原始切片；用 TopHat / cuCIM 校正的通道**只**读 Step 0 保存的校正结果。如果保存的校正结果缺失或对不上（别的区域、别的参数、别的切片），Step 4 **在量任何东西之前就停下**并说明原因——不会退回原始数据，也不会现场重新校正。遇到这种情况请在 Step 0 重新保存校正。

**怎么操作：** 这一页与其他步骤共用标题栏和最下面一行（**← Back to Step 3**、**Batch...**、**⏹ Stop**、**▶ Extract Features**），设置在中间排成一栏。

1. **Run** 与 **Region**：Step 4 打开时就是你在 Step 3 选的那个结果（没有选过时是最近一次 Step 2 的结果）。`Browse` 可以另选运行文件夹；一个运行有多个区域时可以选其中一个。**Slide** 是这个运行自己的切片，不能另选。下面一行写明有多少个细胞、多少个通道读原始数据、多少个读 Step 0 的校正结果。红字说明为什么这个结果不能定量，例如：Step 2 还没有保存标签存储（label store）之前做的旧结果（请重跑 Step 2）、别的切片上的结果、缺少 Step 0 的校正结果。
   - 纯核方法的结果（如 StarDist nuclei）没有细胞 mask：这时按核来定量。
2. **What to quantify（定量范围）**——四组（点标题左边的箭头可以折叠）；只计算勾选的内容：
   - **Statistics**：Mean、Sum、Std dev、Min、Max（默认全选）。下面一行 **Distribution (slow)**：Median、P90、P95、Gini——默认不勾；勾了任一项会出现 marker 列表，只勾你需要的几个（例如 FOXP3、Ki67）。它们要用到每个细胞的全部像素值，每个 marker 要多读一遍；没有勾任何 marker 时 `▶ Extract Features` 不可用。
   - **Expression regions**（只作用于表达量）：Whole cell（总是有）、**Nucleus**、**Cytoplasm**。核 = 细胞自己的核的像素；胞质 = 细胞里其余的像素。结果在细胞旁边保留了核时（expansion 与 nuclear-guided 方法）可选并默认勾上。例如转录因子（FOXP3、Ki67 → 核）与膜标记（CD3 → 全细胞 / 胞质）一起用于细胞注释。
   - **Features**：Expression（总是有）、Morphology（默认勾）、Nuclear summary（每个细胞：核数、核在细胞内的面积、平均 / 最大核面积、核占比、胞质面积）。
   - **Outputs**：h5ad（总是有）、**CSV**（只有勾选时才输出）。
   - 对 Step 2 接缝修复（2026-09-27）之前做的结果定量核 / 胞质时，会出现橙色的 **Risk** 提示：接缝上少数核可能有一部分不在自己的细胞里，这些细胞的核 / 胞质数值带有这个误差；数值照样输出，来源记录里写明受影响的像素数。重跑 Step 2 即可消除。
3. **Output dir** 默认是 `<工作区>/step4/quantification_runs/<运行>/<区域>/`，可以改。下面一行写出输出文件名与 `X` 是什么（例如 `X = cell mean`）。点 `▶ Extract Features`。

**产出：**
- `cell_features.h5ad`——**一个** AnnData（给 scanpy 用），一行一个细胞（纯核结果一行一个核）：
  - `X`：全细胞按 mean → sum → std → min → max 顺序取的第一个勾选的统计量（`uns["X_statistic"]` 写明）；
  - `layers`：每个勾选的组合一张，名为 `<区域>_<统计量>`——`cell_mean`、`nucleus_mean`、`cytoplasm_max`……（也包括 X 的那一张，X 被归一化之后仍有原值）；没有像素的区域（没有核的细胞）为 NaN；
  - `obs`：`cell_id`、形状列与核汇总；`var`：每个通道及其来源（原始 / Step 0 的校正结果、方法与参数）；`uns`：X 的含义、区域与完整的来源记录。
  - `obsm`（只在选了分布统计时）：每个「区域 × 统计量」一张表——`obsm["cell_median"]`、`obsm["nucleus_p90"]`……——列是勾选的 marker，例如 `adata.obsm["nucleus_median"]["FOXP3"]`。中位数与分位数按 numpy 的定义（`np.median`、线性插值的 `np.percentile`）；Gini 按排序后的像素值计算（像素全为 0 时为 NaN）。
- `cell_features.csv`（只在勾选时）：同一张表，一行一个细胞；全细胞列名为 `<通道>_<统计量>`，其余为 `<通道>_<区域>_<统计量>`。
- 形状列：`area`（面积）、`centroid_y` / `centroid_x`（质心）与外接框 `bbox_min_y`、`bbox_min_x`、`bbox_max_y`、`bbox_max_x`（max 不含），都是切片像素坐标；`major_axis`、`minor_axis`、`eccentricity`、`orientation`（与 scikit-image `regionprops` 相同）、`equivalent_diameter`（等效直径）、`aspect_ratio`（长宽比 = 长轴 / 短轴；短轴为 0 时为空）、`extent`、`boundary_pixel_count`——细胞里 3 × 3 邻域中碰到别的细胞或背景的像素数（质控用的计数，**不是**旧的 `perimeter` 列，旧列漏掉了两个紧贴细胞之间的边界）——然后是 `perimeter_crofton`，用 Crofton 公式估计的周长长度（像素，与 scikit-image 的 `perimeter_crofton` 相同，4 个方向），以及 `circularity` = 4π × 面积 / perimeter_crofton²（正圆为 1；很小的细胞周长难以估准，可能略大于 1——按计算值保留）。
- `cell_features_provenance.json`：量了什么、从哪里读的——运行与区域、每个通道的来源、没有像素的编号、（旧结果的）不在自己细胞里的核像素数、耗时。
- 旧版本的长短轴与偏心率在离图像原点远的地方有舍入误差；这个版本的数值在那里与旧表格不同（有意修正）。
- **Batch...** 为每个样本写 h5ad；要 CSV 时在那里勾 `Also write CSV`。

## 六、常见问题（FAQ）

| 问题 | 可能原因 / 解决 |
|------|----------------|
| 启动报 `No module named block01` | 没有在**上一级目录** `analysis_pipline` 里运行，或没用 `python -m block01.main` |
| 细胞圈得很糊 / 粘连 | 回 Step 1 调通道权重和分割参数；背景可能扣得不够或过头（Step 0） |
| Step 2 跑到一半显存不够 | 把 Tile 瓦片调小；确认用的是 GPU 而不是 CPU |
| Step 2 中断了要重跑？ | 用 Step 2 的 **Recovery Mode**，从已存的中间文件继续合并 |
| 想换个 ROI 重做 | 回 Step 0 重新画 ROI；各 ROI 的结果分目录保存，不会互相覆盖 |
| 关了软件参数还在吗？ | 在，Step 1 有 **Save / Load Session**，会写 `step1_session.json` |

## 附录 A · 分割方法怎么选？（看不懂就先用默认）

软件里能选多种"把细胞圈出来"的算法。**新手直接用默认的 Cellpose 即可**，下面只是简单说明区别：

| 方法 | 通俗解释 | 什么时候用 |
|------|---------|-----------|
| **Cellpose whole-cell (Fusion + DAPI)** | 用"融合轮廓图 + 细胞核"直接圈**整个细胞** | 默认首选，大多数情况 |
| **Cellpose nuclei (DAPI)** | 只圈**细胞核** | 只关心细胞核，或膜染料不好 |
| **Cellpose nuclei + expansion** | 先圈核，再向外"膨胀"一圈当作细胞 | 没有好的膜信号时的近似方案 |
| **Cellpose nuclei + HQ / HQ2** ⚠️ | 先圈核，再用结构通道做更精细的细胞质扩展 | **仍在测试、尚不成熟**，谨慎用于正式分析 |
| **Cellpose nuclei + CDS** ⚠️ | 先圈核，再按信号做"甜甜圈式"约束扩展 | **仍在测试、尚不成熟**，谨慎用于正式分析 |
| **StarDist nuclei (+expansion)** | 另一种圈核算法（适合密集圆形核） | 核很密、很圆时 |
| **Mesmer (whole-cell / nuclei / nuclear-guided)** | 专为组织影像设计的整细胞分割 | 有清晰膜通道，想要整细胞分割 |

> ⚠️ **注意**：标 ⚠️ 的 **HQ / HQ2 / CDS 方法目前仍在测试、尚未成熟**，结果可能不稳定，请勿用于正式产出，优先选用 `Cellpose whole-cell`。
>
> 简单原则：**先用 `Cellpose whole-cell` 跑一遍看效果**，不满意再换。每种方法的细节参数都有界面，不动它们通常也能用。

## 附录 B · 名词小词典

- **通道 / Channel**：一种染料点亮的一类东西，对应大图里的一"层"。
- **ROI（Region of Interest）**：你框出来要分析的区域，避免处理整张巨图。
- **DAPI**：常见的细胞核染料，软件默认拿它当"细胞核通道"。
- **融合 / Fusion**：把多个通道叠成一张轮廓图，方便算法找细胞边界。
- **分割 / Segmentation**：把图里每个细胞各自圈出来的过程。
- **掩膜 / Mask**：和原图一样大的一张"编号图"，每个细胞一个号，背景是 0。
- **瓦片 / Tile**：把大图切成的小格子，分块处理省内存。
- **特征 / Feature**：每个细胞被量出来的数值（各通道亮度、面积等）。
- **`.zarr`**：一种支持"只读用到的那一小块"的大数组格式，省内存。
- **`.h5ad`**：单细胞分析常用的标准表格格式（scanpy 等直接读）。
