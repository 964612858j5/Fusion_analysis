## 一、先复现（改动前）

台架为 scratchpad 脚本（**未入库**，白名单不允许新增 `scripts/`），复用 5A 的真机窗口构建流程，
`QT_QPA_PLATFORM=offscreen`，窗口宽 1400/1200/1000，patch 数 0/1/7/8/20：

| 窗口宽 | patch 数 | 按钮数 | 按钮条宽 | 最后一个按钮 x → 右缘 | Viewer viewport |
|---|---|---|---|---|---|
| 1400 | 7 | 7 | 318 | 669 → 711 | 1122×637 |
| 1400 | 8 | 8 | 364 | 715 → 757 | 1122×637 |
| 1400 | 20 | 20 | 916 | 1267 → **1309** | 1122×637 |
| 1200 | 20 | 20 | 838 | 1155 → **1197** | 960×637 |
| 1000 | 20 | 20 | 676 | 963 → **1005（超出窗口宽 1000）** | 798×637 |

结论（如实限定）：

- **已复现的是「按钮条无上界增长」**：每个 patch 固定 42 px + 4 px 间距，20 个 patch 时条宽 916 px，
  1000 px 窗口下最后一个按钮的右缘已经**落到窗口之外**。这与用户反馈的「太宽」一致。
- **本台架不能证明 P8「点不到」，也不能证明它「点得到」**：`QTest.mouseClick` 直接把事件投递给
  widget，对一个右缘在窗口之外的按钮同样会「成功」并进入 `_select_preview_patch`。
  能作为证据的只有上表的几何数字。
- 同一批测量中 **Viewer viewport 未因 patch 数变化而变化**（1122×637 / 960×637 / 798×637 恒定），
  即这是选择器行宽问题，不是视口问题。

## 二、生产改动（`ui/main_window.py`，唯一文件）

1. 新增模块常量 `STEP1_INLINE_PATCH_BUTTONS = 7`。
2. 选择器行的标题 `QLabel("Preview patch:")` 换成固定高度的 `QToolButton("Patch")`
   （`InstantPopup`）+ 其 `QMenu`：**标题与下拉入口是同一个控件**，没有新增第二个按钮。
3. `_rebuild_patch_buttons()`：内联按钮最多建 7 个；同一次调用里用
   `_rebuild_patch_menu(len(patches))` 按 patch 顺序重建菜单项（**每个 patch 一项，全量**）。
4. 菜单项 `triggered` 一律连到**既有的** `_select_preview_patch(idx)`；菜单不知道如何选中 patch，
   只知道请求选中。
5. 新增 `_sync_patch_selection_marks(idx)`：内联按钮与菜单项的勾选由同一处写入；
   `_on_patches()` 与 `_select_preview_patch()` 原先各自的 `setChecked` 循环改为调用它。
6. 新增 `_patch_btn_state(idx)` / `_patch_btn_label(idx, state)`：状态仍旧从既有的
   `_patch_load_ready` / `_patch_loaders` 读取，**没有第二份状态表**；
   `_set_patch_btn_state()` 用同一个标签同时刷新内联按钮（若存在）与菜单项。
7. 无 patch 时 `Patch` 入口保留但 `setEnabled(False)`。
8. **（局部收口）** 把按钮尺寸与行间距从字面量提升为 `STEP1_PATCH_BTN_W = 42` /
   `STEP1_PATCH_BTN_H = 22` / `STEP1_PATCH_BTN_SPACING = 4`，并由此派生
   `step1_patch_menu_width() = 7*42 + 6*4 = 318`；下拉菜单以此为**宽度下界**
   （构建时与每次 `menu.clear()` 后各设一次）。

**没有**新增第二份 patch 模型，**没有**新增第二个选择权威，**没有**新增按钮，
**没有**触碰 G3.2b.5A 的晃动问题、GPU layer、相机或几何链路。

## 二之二、下拉宽度收口（用户指出的缺口）

- 收口前：菜单宽度未设置，Qt 默认按最长标签给宽。**实测 20 项菜单宽 250 px**，
  与 318 px 的按钮条并不对齐。
- 第一版收口用了 `setFixedWidth(318)`，**被本块自己的门抓出是错的**：
  在 800×600 的 offscreen 屏上，20 个 32 px 高的菜单项装不下 600 px，
  **Qt 会自动分栏**，实测 `sizeHint = 636×576`，P19/P20 落在 `x=318`；
  硬设 318 px 宽会把第二栏整个裁掉，**恰好这两个 patch 变成点不到**
  （`test_a_real_click_selects_p20` 当场变红）。
- 最终实现为**宽度下界** `setMinimumWidth(318)`：
  - 能一栏放下时（本屏上 ≤ 18 项、真机 1080p 下 20 项也够）菜单**正好 318 px**；
  - 需要分栏时**每一栏仍是 318 px**（实测 636 = 2×318，每个菜单项矩形宽 318），
    且所有菜单项都在弹出矩形内。
- 未改选择逻辑，未改白名单外的两个 benchmark 脚本。
