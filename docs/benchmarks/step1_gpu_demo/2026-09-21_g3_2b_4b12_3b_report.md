## 0. 一句话结论

漂移**不是**返回路径的误差，也**不是**布局或 aspect lock 的误差 —— 逐段实测那些**全为 0.000000 屏幕像素**。
它完全来自一条语义：**“Compare here”把鼠标下的世界点变成 Compare 中心，而离开时无条件把这个中心带回 Full Image。**
鼠标停在固定屏幕像素上，每轮那个像素下的世界点都被上一轮挪走了，于是循环单向行走 ——
实测**每轮恒为 (−334, −115) 屏幕像素，正好等于鼠标相对视口中心的偏移**。

最小修复：**离开时先问“用户到底动过没有”**。没动就回到进入前的 Full Image 相机；动过就照旧采纳 Compare 相机。

## 6. 最新产品语义如何实现

`ui/step0/step0_page.py`，三处：

1. **一个不可变三元组** `_compare_entry_panel_camera`（§7 说明为什么必要）；
2. `_enter_compare_mode()` 在 `_apply_compare_camera(px, py, scale)` **之后**从真实 ViewBox 回读一次；
3. `_returning_full_camera()`：

```python
if self._compare_camera_unmoved_since_entry((cx, cy, scale)):
    saved = self._compare_entry_full_camera
    if saved is not None:
        return tuple(float(v) for v in saved)
return (cx, cy, scale)
```

判定本身：

```python
# SCALE FIRST: 绕着不动的中心 zoom，中心一点没动
if abs(scale - escale) > self._COMPARE_UNMOVED_SCALE_REL * escale:   # 1e-6
    return False
budget = self._COMPARE_UNMOVED_SCREEN_PX                              # 1.0
return abs(cx - ex) * scale <= budget and abs(cy - ey) * scale <= budget
```

**没有做的事：** 没有补偿常数、没有每轮减去固定偏移、没有方向性修正、没有固定 level-0 阈值、
没有依赖分辨率或切片尺寸、没有第二套 ViewBox / 相机控制器 / 事件总线 / 状态机、没有新增按钮。
「Compare here」原样保留。

## 7. 为什么必须新增这一个进入时快照

因为**判断「用户动过没有」需要一个基准**，而现有字段都不能充当：

- `_compare_entry_full_camera` 是 **Full Image** 的相机，与面板的相机相差一个「compare here」的位移；
- 进入时请求的 `(px, py, scale)` 也不行：三个面板各自解自己的矩形，`viewPixelSize()` 还带着
  graphics view 的 device transform，**拿请求值和回读值比会把每一次进入都判成“移动过”**。

所以它必须是**面板真正落位之后的回读**。它**不是第二套相机**：不驱动任何 ViewBox、
从不被应用到任何地方、只在 `_returning_full_camera()` 一处被读。
生命周期：进入时记录、离开时清空、数据集切换时清空 —— 三处都有门。
