# TMA 粗 core 编辑与信息匹配规范（v1 提案）

日期：2026-09-12。状态：讨论共识已固定，尚未实现。

## 工作流

导入切片和地图 → 提出粗 core 区域 → 分段拖线/连续点击编号 → 单颗修正与 CSV 身份确认 → 逐 core 放大标记 blur/fold 排除区 → 校验并锁定版本 → 细胞分割与定量。

支持先圈 core 后导入地图；未确认身份时可存草稿，不发布带样本身份的批量结果。复用现有 viewer、图像读取、ROI 和分析引擎。

## 粗 core 编辑

- 支持新增矩形、椭圆、多边形，移动、缩放、顶点编辑、画笔增加/擦除，以及拆分、合并、撤销/重做。
- 同一 core 可包含多个不连通组织块，以 MultiPolygon 保存；边界不要求贴合组织。
- 区分删除误检候选（软删除）与排除真实 core（保留位置、身份及原因）。
- 已匹配对象删除、拆分、合并后，相关匹配进入待复核，不自动继承可能错误的身份。
- 边界编辑不改变编号。几何或排除区变化使相关 core 分析过期；身份变化使关联结果和汇总待更新。保留旧版本。
- 粗区域表达归属，读取 bbox 单独派生并加余量。bbox 可重叠，不同 core 的归属区域重叠须在锁定前解决。
- 分开保存 core_roi、tissue_mask、exclusion_mask。组织检测不得静默截掉手动新增区域，需重新估计或允许修正 tissue_mask。
- 标注统一保存为原图坐标，整片和逐 core 视图均可编辑。排除区记录原因、通道范围（all 或指定通道），不修改原始像素。

## 用户信息文件

建议首版采用 UTF-8 CSV，一行一个预期地图位置，空位也显式列出；XLSX 后续转换到同一契约。所有 ID 按字符串读取，保留前导零。另用布局 JSON 表达 slide_id、行列数及地图方向。示例均为虚构数据。

| 字段 | 必填 | 说明 |
|---|---|---|
| slide_id | 是 | 稳定切片标识 |
| core_id | 是 | 切片内唯一的逻辑 ID，例如 A01，不因删除而重排 |
| row / col | 是 | 从 1 开始的整数，地图规范方向的位置 |
| slot_type | 是 | sample / control / empty，地图上的计划用途 |
| sample_id | sample 时 | 样本标识，允许多个 core 共用 |
| patient_id | 否 | 去标识化患者 ID；患者级汇总前必须完整 |
| replicate_id | 否 | 样本重复 core 标识 |
| tissue_type / condition | 否 | 组织类型、分组 |
| control_label | control 时 | 对照名称 |
| notes | 否 | 备注 |

唯一键为 (slide_id, core_id)，位置键 (slide_id, row, col) 也必须唯一。内部另有不可变 core_uid，避免修正可读编号时破坏引用。sample_id、patient_id 不是 core 唯一键。

地图预期 slot_type、图像观测 observed_state（present / missing / unexpected）、QC 状态（unreviewed / accepted / excluded）分开。计划样本位置找不到组织记录 missing，不能改为 empty。QC 原因可多选；局部排除不等于整颗排除。

地图 row 从上向下、col 从左向右。扫描图像的旋转/镜像需独立确认，不能从该约定推断。

## 对应到图像 core 的方法（已确认共识）

首版主流程：**分段拖线批量编号、连续点击顺序编号、单颗编辑精确修正**。用户指定顺序与身份，软件负责选取、排序、预览和一致性校验。全阵列自动拟合为后续辅助，不是前置条件。

### 分段拖线

用户沿一行、一列或任意方向从起点拖至终点，指定起止编号与目标 CSV 记录序列。显示可调宽度的半透明选取带，按 core 代表点在线段上的投影距离排序；支持移除误选、补选及反转顺序。确认前逐项预览图像 core 与 CSV 记录的对应。

编号范围解析为 CSV 中实际存在的记录，横向、纵向或自定义记录顺序在预览中明确，不按字符串加一补造 ID。每条线独立指定目标序列，校验本段 core 数量与记录数一致，数量一致仍需确认对应。

缺失位置通过分段画线绕过，无需强制插入占位符。例如 A04 缺失：第一段三个 core 对应 A01–A03，第二段四个 core 对应 A05–A08。第二段不自动从 A04 开始。CSV 的 A04 保留未匹配，用户可确认为 missing；软件不将所有未匹配记录自动认定缺失。

### 连续点击

按点击顺序建立 core 序列，适合弯曲、错位和不规则排列。支持撤销上一点、顺序预览及修正，再与选定的 CSV 记录序列绑定。此处锚点是用户指定顺序，不要求三个非共线点或仿射拟合。首版直线加连续点击即可，折线可后续扩展。

### 单颗自定义编号

点击单个 core 后直接输入编号，或搜索选择 CSV 记录：

- 编号存在于当前切片 CSV：预览并绑定该记录和样本信息。
- 编号不在 CSV：允许保存自定义 core，标记“信息待补充”，不猜测样本或地图位置；补全有效记录前可存草稿，不发布该 core 带样本身份的分析结果。
- 编号已被其他 core 占用：提供显式交换或重新绑定，不静默覆盖。重新绑定后原占用者成为未匹配/待复核，保留其几何。
- 修改一颗不重新编号其他 core，内部 core_uid 不变，相关关联结果及汇总按版本更新。

CSV 显示行序可以用于选择序列，物理行号不能作为永久身份。绑定保存 (slide_id, core_id) 与内部 core_uid；CSV 排序或插行不改变既有对应。修改 ID 须显式更新并保留历史。

### 校验与锁定

导入校验必填值、枚举、正整数、重复 ID/位置、越界和条件必填字段。预期地图的 rows × cols 个位置显式列出，空位保留；不完整地图及自定义未补全 core 可存草稿并报告缺项。

每个位置最多对应一个逻辑 core，每个 core 最多对应一个位置，多块组织先归为同一逻辑 core。已匹配对象再次选中须提示，不静默覆盖；empty 位置不自动匹配。

锁定前每个地图位置有明确状态，额外候选已匹配、补全信息或明确不纳入。已确认 missing、empty、excluded 合法，不要求检测数等于位置数。重复匹配、归属区域重叠及纳入分析 core 的身份缺失须解决。

人工流程通过逐段顺序与身份确认处理方向，无需额外完成全阵列旋转/镜像拟合。后续自动辅助可以利用确认的对应拟合阵列；启用自动传播时须解决旋转/镜像歧义，不覆盖人工确认结果。

## 内部保存与下游接口

保留原始地图及内容校验值，另存版本化 manifest，不把几何坐标混入用户样本表。

manifest 保存 schema_version、study_id、slide_id、source_image_id、原图尺寸/像素尺寸、map/geometry/mapping/qc 的版本、匹配方式（line / click / single / auto）、每段有序 core_uid 与目标记录键、线段及选取宽度、确认记录、可选阵列变换、操作记录。

每个 core 保存 core_uid、core_id、row/col、样本信息、MultiPolygon、派生 bbox、tissue_mask 引用、观测/QC 状态、排除区、匹配状态及人工确认信息。

规范几何均为原图 level-0 像素坐标：左上原点，x 右向，y 下向，顶点 [x,y]，bbox [x0,y0,x1,y1)。读取下界向下取整、上界向上取整并限制在图像范围。保存 preview→level-0 与 core-local→level-0 变换，屏幕坐标不能直接持久化。

细胞输出携带 slide_id、core_uid、core_id、sample_id、patient_id（若有）、原图/core 内坐标及所用版本。空间邻接按 core 独立建立；同样本的不同 core 不跨 core 建邻接。

## 验收场景

- 删除误检、缺失中间 core 后，其余编号与身份不变。
- 同一 core 的两块组织可归到同一身份；粘连两颗可拆分匹配。
- A04 缺失时，分段映射 A01–A03、A05–A08，无占位操作且无顺移。
- 横向、纵向、斜向拖线与连续点击可预览/反转；段内数量不一致不能提交。
- 自定义未知编号可存草稿并提示信息待补充；占用编号须显式交换/重新绑定。
- 单颗改号不影响其他 core；CSV 排序/插行不改变绑定。
- 自动阵列传播的镜像歧义必须确认，重复位置/编号拒绝导入，同样本重复 core 正常导入。
- 放大编辑与原图叠加一致，保存重载无坐标漂移。
- 局部排除可撤销，整颗排除保留地图位置，原始图像保留。
- 几何变更使相关分析过期，旧结果仍可追溯。

实现顺序：粗 ROI 编辑 → 地图导入与校验 → 分段拖线/连续点击/单颗编号及预览确认 → 排除区与版本锁定 → 现有 ROI 分析入口。全阵列自动拟合作为后续辅助。
