### 1B 选项 2：直接读已有合并 OME-TIFF
- **已核事实**（只读）：`/sdb1/cop/Kevin/test4/FINALRUN_updated_TMA4_Scan1_bgcorrected.ome.tiff`：单主 series，69 × 46800 × 26880，uint8，512 分块，Deflate，6 层；通道名与顺序同 `_channels.csv`，无重复；65 个校正通道、4 个原图通道；各层尺寸与原 qptiff 一致。生成脚本 `/sdb1/cop/Kevin/merge_corrected_to_ometiff.py`：校正通道 `rint` 后以 1e-3 容差统计非整数、裁到 0–255 转 uint8；**缩小层是逐层从上一层 uint8 做 2×2 平均、每层舍入**（原图通道的缩小层也是这样重建的）。
- 所以：**全分辨率层"通过导出检查，严格相等待抽样核验"**；**缩小层与我们的块平均算法不同**，数值会有差异，单独报告，不作逐像素通过依据。
- **先核验（只读、在私有只读挂载视图内）**：每个测量通道，全分辨率若干块（含边缘）OME-TIFF 值 == 校正结果的值；不相等则 1B 停止，报告。
- **显示替代约定**（本步只支持已核验的 full-WSI 快照：bbox `[0,46800,0,26880]`；其他 ROI 回原路径）：
  - 通道映射：按唯一通道名取 TIFF 索引；并核对该通道就是当前校正产品（测量前记录校正产品的 `source_identity` 与导出时间；本步以固定只读快照为前提）；
  - 坐标与有效区：TIFF 为全片坐标；有效区沿用现有规则（包围框内有效、合法 0 是样本；多边形外由现有渲染裁切）；

  - 身份：构建清单时记录 OME-TIFF 的 FileId，打开与重绑时由现有 `reader.rs` 校验（只证明是那个文件）；"它对应当前校正产品"由上条快照前提保证；回退原路径时日志记录实际来源；
  - 科学边界：只替代显示；校正通道在分割、分析、保存中的语义和数据不变。
- **接入（测量用开关，不作产品入口）**：`BLOCK01_STEP1_DISPLAY_OMETIFF=<路径>`。Rust 新增一种来源"显示用 TIFF"（第二个原图读取源，按通道索引读 u8），图块走现有 U8 格式（`family.rs` 已有 U8，`store_plan.rs` 通用分配，不改这两个文件）；CPU 缓存分类计入校正额度。产品化（登记、失效、谁生成）看结果后另请用户裁定。

## 3. 第 2 步：视野外预读（off / odon / limited）

在第 1 步选定的数据上做；**本步保持我们现行的层选择、最粗层整层请求与发布门不变**（这些属第 3 步），只改"目标层的请求范围"。"odon"一列**照用 Odon 的预读规则，但有意适配**：Odon 对当前请求的各层都做 pad1，本步只对目标层做（其余层在第 3 步 odon 策略里照用）；Odon 的 adaptive 辅助层限制、pinned 暂停不适用（我们无此两种机制），不新增：

| | off | odon（原样） | limited |
|---|---|---|---|
| 目标层基础范围 | 可见块（现行） | 可见块外扩 1 块（pad1） | 可见块（现行） |
| 额外圈 | 无 | 以 pad1 后的位置数 n 判断：n ≤ 16：pad2 减去 pad1，最多 48 个位置；17–48：pad1 减 pad1（即空）；> 48：无；位置数再乘通道数 | 可见外扩 1 圈减可见块 |
| 总量 | — | 照 Odon：每帧新发请求最多 256 个（图块 × 通道），基础与额外共享；已在途或已缓存的不重复发；不是在途上限（`app.rs:13186-13187, 15103-15155`） | 全窗口最多 48 个（图块 × 通道） |
| 在途 | — | 不另限 | 预读最多 1 个在读 |
| 顺序 | — | 照 Odon：pad1 集合（含可见块）整体按中心距离排，额外圈排在其后（`app.rs:12990-13010, 14984-15023`） | 可见 → 预读，按中心距离 |
| 关闭额外圈 | — | 照 Odon：渲染通道 ≥ 16，或 各请求层 pad1 位置数之和 × 通道数 超过缓存的**图块槽位数**（我们按 CPU 校正缓存字节 ÷ 每块字节换算槽位；`app.rs:13013-13034`）；**pad1 本身不关** | 预算紧张、可见请求积压、carry 为 0 |
| 上传 | — | 只上传绘制列表（与屏幕相交）的块；屏外留 CPU（Odon 普通无偏移 XY 视图如此，`app.rs:13367`、`tiles_gl.rs:212`；通道偏移/affine 时 Odon 放宽绘制范围，我们无此功能） | 同左 |

两者都：预读键计入"仍需要"，读完进 CPU 缓存（现有 worker 先缓存后交付的机制），不被当过期丢掉；进入视野后走正常取用；admission 先按可见算，预读不让可见目标降粗；不新增缓存、不加总额度；视野变化替换未开始的预读。

记录：pad1 后位置数、额外圈实际数量、关闭原因（否则可能没触发第二圈却宣称比较过）。
benchmark：第 1 步尺子；off / odon / limited；另加"立即反向拖"与"远跳"路线（先按 R6 方法标定参考图）；报告预读命中、读了没用的块数、可见请求排队、内存峰值。用户选默认。
白名单：Rust `plan.rs`、`plan/draw.rs`（只限范围与列表）、新 `plan/prefetch.rs`（≤ 约 200 行）、`geom.rs`（外扩覆盖）、`viewer.rs`（只限 `issue()` 的排序、限额与开关 `BLOCK01_STEP1_PREFETCH`）、`pool.rs`、`pool/worker.rs`（预读"仍需要"与在途限制）、`frame.rs`（只限屏外不上传）；测试 `native/.../plan/prefetch_tests.rs`、`tests/test_v16_5_r7c2_prefetch.py`；测量文件 `/sda1/Fusion/a9_bench/r7c/`：`run_r7c2.sh`、`an_r7c2.py`、新路线 `paths/*.json` 与参考图（用现有 `r6/make_scen.py`、`scripts/a9_r6_ref.py`、`a9_r6_calib.py` 标定，不改这些工具）、报告 `R7c2_results.md`。

## 4. 第 3 步：请求层、顺序、粗层范围、首次出现（以丝滑为准）

三套完整策略，均固定使用第 2 步选出的预读配置：

| | cur | odon | hybrid |
|---|---|---|---|
| 请求层 | 最粗层 + 目标层 | 最粗层 + 目标+1 + 目标；放大时加到 sticky ceiling 为止的各层 | 最粗层 + 目标；目标+1 只在目标缺块时、在 carry 剩余内请求，目标齐了停 |
| 每层范围 | 最粗层整层；目标层按第 2 步 | 每层可见外扩 1 块 | 最粗层：可见外扩 1 块 + 已缓存的保留；目标层按第 2 步 |
| 顺序 | 最粗层 → 目标 | 目标 → 目标+1 → 最粗层 → 预读 | 目标 → 目标+1 → 最粗层 → 预读 |
| 首次出现 | 最粗层整层到齐才画该通道 | 到哪画哪 | 当前视野被覆盖齐（任意层）才画该通道 |
| 缩小时 | carry 内保留旧块（现行） | 同现行（不采用 Odon 400 ms floor，codex 查明其延长分支不可达） | 同现行 |

评价：新增"勾选一个新通道"和"跨级放大/缩小"路线。R6 定位只适用平移，所以这两条另写评价方法：稳定终点逐像素比较 + 逐帧记录"有无从中心外扩、有无洞、多久出齐"，辅以人工逐帧验收；方法先交 codex 审再用。拖动、缩放照第 1 步尺子。选最丝滑的一套作默认。
白名单（本步明确授权的行为，不受第 2 步"只限范围与列表"的限制）：
- Rust `plan.rs`：请求层集合（目标+1、sticky ceiling 历史状态与重置）、最粗层请求范围、各层 pad1、首次发布规则的状态；
- `plan/draw.rs`：首次发布门（现 `draw.rs:50` 的 `coarse_complete` 判断）按策略改写、绘制列表；
- `viewer.rs::issue()`：三套策略的请求顺序与开关 `BLOCK01_STEP1_ORDER=cur|odon|hybrid`；
- `admit.rs`（只限范围计算）、`frame.rs`（上传顺序随绘制列表，不改预算）、`plan/prefetch.rs`（与预读衔接）；
- 测试 `native/.../plan_tests.rs`、`tests/test_v16_5_r7c3_order.py`；
