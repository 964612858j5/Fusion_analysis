## 一、用户裁定（2026-09-23）

Step1 通道勾选框的含义在 **Overlay 与 Fusion 两种模式下一致**：**「这个通道现在是否显示」**。

- 取消勾选：只从**当前显示**中移除该通道的贡献。
- **不得**改动 nucleus 通道与权重、group/channel 权重、Fusion Settings、Save 配置或会话权威。
- 重新勾选：从模型恢复，驻留时**零重新读取、零重新上传**。

裁定之前的语义是「Fusion 只看权重，勾选无发言权」（`_effective_fusion_config()`
注释「Display visibility has no vote in it」）。该语义对**持久科学配置**仍然正确，
本次只改**当前显示帧的贡献者集合**。

### 前两轮为什么是绿的（如实记录，不掩盖）

- **round 2：M5 / M5b / M6 全绿**，原因**不是产品正确**，而是**台架从未进入 Fusion 预览模式**：
  `fusion_ready()` 只设了 `mount.set_mode(FUSION)`，`window._step1_preview_mode` 仍是 `overlay`，
  于是 `tissue_render_snapshot()` 与 `_needed_channels()` 的 Fusion 分支**根本没被执行**，
  我的断言是在对 `None` 求值——**三条假绿**。
  修法：台架改走产品自己的 `window.set_preview_mode(STEP1_PREVIEW_FUSION)`，
  并在读贡献者之前断言 `tissue_render_mode() == "fusion"` 与 `tissue["mode"] == "fusion"`。
  同批修掉另外两处空断言：Fusion 快照**没有** `channels` 键（原断言永不可能失败，改为断言
  `arrays` 这个真实读取集合），以及 `set_current_channel(MARKER)` 未生效时 M6 断言被条件跳过
  （改为断言当前通道确实移动了）。
- **round 3：M5 仍绿，这是真实的覆盖缺口**，不是台架缺陷：那条门里唯一被取消勾选的是 nucleus，
  而 nucleus 不属于任何 group，因此「groups 不过滤」在该场景下**不可观测**。
  补上「取消勾选一个 **group 成员**、nucleus 保持勾选」的场景（画面非空，缩略图仍能合成），
  round 4 才 7/7。

## 七、旧语义门的改写（白名单追加，用户 2026-09-23 授权）

`tests/test_step1_gpu_takeover.py` 中三条门**编码了旧语义**：夹具 `visible=("CD3",)`
让 CD8 / DAPI **处于未勾选状态**，却要求「把权重调上去就必须请求 Intensity window
并进入 GPU submission」——即「Fusion 里权重单独决定参与，勾选无发言权」。

| 门 | 改写 |
|---|---|
| `test_a_zero_channel_weight_is_never_given_an_intensity_window` | 四阶段 |
| `test_a_zero_group_weight_is_never_given_an_intensity_window` | 四阶段 |
| `test_a_zero_nucleus_weight_is_never_given_an_intensity_window` | 四阶段 |

四阶段结构（`+104 / -0`，**未删除任何测试，未降低任何 weight 断言**）：

1. 未勾选 + 权重 0 → 无 seed、不在 notice（**原断言原样保留**）；
2. **只动勾选**，权重仍 0 → **仍无 seed**（新增；有效权重为 0 时两种勾选状态都不请求窗口）；
3. **只动权重**，勾选保持 → `seeds.count(...) == 1`（**原断言逐字保留**）；
4. 取消勾选 → 不再请求 seed、退出 GPU submission、**权重 / group 权重 / nucleus 权重不变**（新契约）。

**为什么不是「一开始就勾选、让 weight 成为唯一变量」**（用户提议的字面做法）：
在构造时给 `visible=("CD3","CD8")`，夹具会**立即**为 CD8 请求 Intensity window
（`set_mode(LEGACY_FUSION)` 之前 Overlay 需要给已显示通道一个窗口），
这会直接摧毁该门赖以存在的第一条断言 `"CD8" not in seeds`。实测如此（三条门同时红）。
因此把勾选放进**单独一个阶段**，才能既让 weight 成为阶段 3 的唯一变量、
又一字不改地保住原断言。阶段 2 反而**加强**了该门自己的论点：有效权重为 0 时，
勾选与否都不给窗口，所以阶段 3 的那一个 seed **可证明属于权重**。

每条门的 docstring 都注明：2026-09-23 用户显示语义裁定、旧夹具当年默认断言了什么、以及勾选为何独立成段。
