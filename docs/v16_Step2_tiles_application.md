## 1. 必要性与目标

1. **显示修复**：计算期间改动行 / 列数，再改回计算用的网格时，已经完成的 tile 应恢复为绿色，正在计算的 tile 应恢复为黄色。计算本身不受影响，今天也确实不受影响。
2. **空 tile 跳过**：用户可以选择跳过没有组织的 tile。被跳过的 tile 不送进分割引擎，从而节省推理时间、内存和显存。
   - 这是**可选**功能，默认关闭。
   - 关闭时，Step2 的输出与今天逐位相同。

## 2. 只读调查结果

### 2.1 tile 状态显示（`ui/step2_page.py`）

- **网格的画法**：网格是概览图上的一组 `pg.RectROI`。每个格子的状态在 `self._tile_rects`、`self._tile_status` 两个字典里（`:169-170`），键是 `(row, col)`。
- **`_draw_tile_grid`**（`:1598-1631`）：行列数取自界面的 spin box（`:1602-1603`），**不看正在运行的网格**。它会删掉所有格子、**清空 `_tile_status`**（`:1606-1609`），再全部重建为灰色（`:1621`、`:1630`）。
- **改动行 / 列数时**：`_rows_spin` / `_cols_spin` / `_overlap_spin` 的 `valueChanged` 都接到 `_update_tile_info`（`:402-404`）。它最后会调用 `_draw_tile_grid`（`:1547`），中间没有「正在运行」的判断。运行期间这些控件也没有被禁用：开始运行时只禁用了 Run 和 Back（`:2538-2540`）。
- **worker 到格子的映射**：
  - worker 只发出 tile 的序号：`tile_done(i, n_tiles, n_cells)` 和 `progress(i, n_tiles, msg)`（`workers/segment_merge_worker.py:120-123`）；
  - 页面用运行开始时记下的 `_n_rows` / `_n_cols`（`:2480-2483`）按行优先换算成 `(r, c)`（`_on_progress` `:2564-2573`、`_on_tile_done` `:2575-2582`），然后**画到当前显示的那套格子上**；
  - tile 的顺序确实是行优先（`utils/tile_scheduler.py:41-42`）；
  - 「正在计算」只画了颜色，没有记进 `_tile_status`（`:2573`）。
- **灰框的确切原因**：
  1. 用 3×4 开始运行；
  2. 改成 6×4 时，`_draw_tile_grid` 清空了全部状态；
  3. 6×4 期间完成的 tile k，被画在 6×4 网格的 `(k//4, k%4)` 上（键存在，但对应的图像区域不同）；
  4. 改回 3×4 时又清空一次，没有任何地方把运行进度重新画回来。

  根本原因是：**运行进度只保存在可随时丢弃的显示对象上，没有一份独立于显示的运行记录**。
- **多 ROI**：worker 对每个 ROI 的 fused zarr 单独切 tile，序号从 0 重新开始（`:2589`）。页面只显示一个 zarr 的网格（`:1480`），所以多 ROI 运行时，各个 ROI 的进度会叠画在同一套格子上。单 ROI（包括 Full WSI）没有这个问题。见裁定 5。
- 没有任何测试覆盖这个状态显示（`tests/` 里 grep 不到相关名字）。

### 2.2 tile 循环与空 tile（`workers/segment_merge_worker.py`）

- **两套几乎相同的循环**：ROI 循环 `_segment_one_zarr`（`:2548`，循环体 `:2684-3034`），和全图循环（`run()` 中的 `:3628-~3970`）。本块的改动两处都要做。
- **空 tile 本来就合法**：引擎返回空掩膜时，`n_raw == 0` 分支（`:2894-2903`）记一行剖析、发出 `tile_done(i, n, 0)`、`continue`；不进 `tile_stats`，也不调用 `add_tile`。跳过可以完全照这条路径走。
- **接缝合并能容忍缺 tile**：
  - `SeamMerger` 只在有接缝候选时才写溢出文件，读取时按 glob 找（`core/seam_merge.py:384`、`:428`）；
  - 邻居 tile 里伸进被跳过 tile 的细胞，会成为单 tile 组件，并被保留（`seam_merge.py:206-211`）；
  - 所以只要被跳过的 tile **本来就分不出细胞**，最终掩膜与不跳过时相同。
- **两个必须处理的点**：
  1. **DAPI 输出**：每个 tile 读取后都会把自己那块 DAPI 写进全图 DAPI（`:2734`）。跳过的 tile 仍然要读这一块，否则 `global_dapi*.ome.tiff` 那里会变成 0。
  2. **预读器**：`TilePrefetcher._fill` 会按顺序提前提交后面的 tile，没有被取走的 future 不会被丢弃（`utils/tile_prefetch.py:79-89`）。如果循环在 `load_tile(i)` 之前就 `continue`，预读队列会被这些死条目占满，之后的 tile 全部退化为同步读取。所以**跳过的判断必须放在读取函数里面**（`:2661-2666`、`:3611-3616` 接的 `_prepare_tile_payload`，`:1813`）：被跳过的 tile 只读 `dapi_own`，返回一个占位的 payload。
- **恢复模式**：`recovery_npy_dir` 会关闭预读（`:1809-1810`），本块不在恢复模式下跳过。

### 2.3 现有的组织检测

- `core/random_patches.tissue_mask(signal, ds, params)`（`:52-89`）是现成、经过测试的组织掩膜：log → 稳健归一化 → 高斯 → Otsu → 闭运算 → 填小孔 → 去小块。参数按第 0 层像素给出（`PARAMS_L0`，`:35-36`）。
  - 今天唯一的调用方是 Step1 的随机 patch（`ui/step1_presegmentation/random_job.py:42`）。它读原始切片 DAPI 在约 16 倍下采样的那一层（`pick_mask_level`，`:40`）。
  - 掩膜只在内存里，从不落盘。
- 其他名字里带 tissue 的东西都不是组织检测：`tissue_compose`、`tissue_log`、`OVERVIEW_DOWNSAMPLE`，以及 HQ2 的 Otsu。

### 2.4 选项与记录

- **UI 位置**：Step2 的 Tile Grid 框（`ui/step2_page.py:360-405`）。新的复选框放在 overlap 那一行之后。
- **传到 worker**：经 `get_seg_config`（`:2018-2033`）进入 `seg_config`。`normalize_segmentation_config` 会原样保留未知键（`utils/segmentation_config.py:475-478`），worker 用 `_config_bool` 读取（`:222`）。

## 3. 做法与提交切分（每段都可以单独回退）

### 3.1 第 1 段：显示修复（只改 `ui/step2_page.py`）

- 新增一份**运行进度记录**：开始运行时创建 `self._run_progress = {"grid": (nr, nc), "state": {tile_idx: "running" | "done" | "skipped"}}`。`_on_progress` / `_on_tile_done`（以及第 2 段的 `_on_tile_skipped`）**先写记录，再上色**。
- `_draw_tile_grid` 重建格子之后：如果当前显示的网格等于运行网格，就把记录里的状态全部重新画上，包括 done、running、skipped（裁定 2）。
- **显示网格与运行网格不同时（v2，用户裁定）**：新网格上**不显示任何状态**，所有格子都是灰色。这期间到达的 progress / done / skipped 事件**只写进记录，不画到新网格上**，因为新网格的格子对应的是另一块图像区域。只有改回运行网格时，才把当前的全部状态画出来。
  - 例子：用 3×4 启动，改成 4×6 → 4×6 全灰，不画任何状态；改回 3×4 → 显示到此刻为止的全部状态（已完成、正在计算、已跳过）。
- 运行结束（完成、出错或停止）后，记录保留到下一次运行开始，所以结束后改动网格再改回来，最终状态仍然能看到。
- 运行期间，行列数旁边显示一行小字「当前运行：3×4」，让用户知道哪个网格能看到进度（裁定 2 的一部分）。

### 3.2 第 2 段：可选的空 tile 跳过

- **组织掩膜的来源**（裁定 3，推荐 (a)）：
  - 运行开始时，用 `OmeTiffSource` 读原始切片 DAPI 在约 16 倍下采样的那一层，调用现成的 `random_patches.tissue_mask` 得到全片掩膜，只算一次；
  - 坐标换算用 A3 的 `SlideFrames`：ROI 内的 tile 坐标加 ROI 原点得到全局坐标，再换算到该层坐标；
  - `core/` 下新增一个小模块 `core/tile_tissue.py`：
    - 给定 tile 的 `read_bbox`（**含 halo**）和区域原点，判断这个 tile 是否「没有组织」；
    - 判定规则：该 tile 的读取窗口（含 halo）在掩膜里**一个组织像素都没有**，才自动建议跳过（裁定 4）。
- **由谁决定跳过哪些 tile（v2）**：
  - 页面在运行之前就算好建议，用户确认后的最终名单交给 worker，worker 不再自己判断：
    1. 勾选「Skip tiles without tissue」后，概览图上被判为空的 tile 显示为「建议跳过」；
    2. **用户可以点击任意格子，切换它跳过与否**：
       - 把一个建议跳过的 tile 改回「计算」，不需要确认；
       - **把一个有组织的 tile 改成跳过，会弹窗确认**：写明这个 tile 的组织占比，并说明跳过后其中不会有任何细胞；用户确认之后才按用户的意见执行（裁定 4）；
    3. 改动行、列数或 overlap 后，网格变了，建议重新计算，用户之前的手动选择清空，并给出提示。
  - 名单经 `seg_config` 交给 worker：`skip_tiles = {"grid": [nr, nc], "overlap": px, "auto": [...], "user_forced": [{"tile": i, "tissue_fraction": f}, ...]}`。worker 先核对 grid 和 overlap 与自己的一致，不一致就拒绝运行（fail-closed）。
  - 没有页面的调用（测试、批处理）不带 `skip_tiles` 时，等同于关闭。
  - 记录里**分开写**两类：自动跳过的，和用户在有组织的情况下强制跳过的（附组织占比）。之后复核时能看出哪些 tile 是用户主动放弃的。
- **worker**（两套循环）：
  - 在 `_prepare_tile_payload` 里，被判为空的 tile 只读 `dapi_own`，返回 `{"skipped": True, "dapi_own": …}`；
  - 循环里遇到 skipped：写 `dapi_mmap`，记剖析，发出新的信号 `tile_skipped(i, n_tiles)`，然后 `continue`，与 `n_raw == 0` 分支相同；
  - `tile_strategy` 里记下 `skip_empty_tiles`、被跳过的 tile 序号列表、掩膜参数和所用的层；
  - 开关关闭时，一行新代码都不会执行（`if self._config_bool("skip_empty_tiles", False)` 守着）。
- **UI**（`ui/step2_page.py`）：
  - Tile Grid 框里加复选框「Skip tiles without tissue」，默认不勾选；
  - 新的格子颜色「skipped」（灰蓝色 `#5a7896`，虚线）；
  - 运行期间这个复选框禁用。
- **概览图清晰度（v2，第 7 题）**：Step2 的 Tile Status 概览图本来就读 zarr 输入（fused 的第 1 通道，即核 / DAPI），但它每隔 32 个像素取 1 个（`ui/step2_page.py:1499`；test1 上只有 483×507），所以放大后是马赛克。
  - 改为按「长边不超过 4096 像素」选择下采样倍数：test1 是 1/4，得到 3860×4054；更大的切片按比例取更大的倍数。网格和点击坐标都经过同一个 `_ov_ds` 换算，不受影响。
  - 实测：fused zarr 按 1/32、1/8、1/4 读取都只要 0.2–0.4 s。zarr 无论隔几个像素取一次，都要解压同样多的数据块，所以几乎不增加时间；内存约 30 MB。
- **文档**：`UI_SURFACE_RULES.md`（Step2 的 Tile Grid 框、tile 状态颜色、点击切换跳过、确认弹窗、概览图分辨率）、`docs/user_guide.md`、`docs/用户指南.md`（Step2 一节加一段：选项是什么、怎么判定、默认关闭、跳过的 tile 不会有细胞）。

## 6. 风险

| 风险 | 对策 |
|---|---|
| 掩膜漏判，把有组织的 tile 当成空的跳过了，丢掉细胞 | 默认关闭；用户主动勾选。保守规则：读取窗口里一个组织像素都没有才跳过。掩膜本身已经过闭运算和填孔（`close_r` = 256 px），会把核之间的空隙连成组织。被跳过的 tile 序号写进记录，用户可以复核 |
| 跳过让接缝合并的计数变化 | 只要被跳过的 tile 本来就分不出细胞，掩膜就逐位相同（S2 门）。计数器的变化是预期的，会记录下来 |
| 预读队列被占满 | 判断放在读取函数里；S4 门检查预读的命中率 |
| DAPI 输出出现空洞 | 被跳过的 tile 仍然读写 `dapi_own`；S2 门对 DAPI 逐位比较 |
| 坐标换算错误（ROI 原点、各层比例） | 复用 A3 的 `SlideFrames`；合成数据上专门测一个原点不在 0 的 ROI |
