C4.5c 为实时 Intensity 修改了合成协调、raw callback 等待及 epoch 去重。用户认定这是未经充分批准的范围失控 P0，要求撤销。

事故提交：`b497fd2`、`0d39e9c`、`6ea702a`。对应 revert：`5fc5a9b`、`1de0c31`、`9550e98`。相关路径已恢复至 `192fca8`。

必须保留事实纠正：用户在回退后仍观察到通道从中央向外扩散。源码显示逐瓦片发布在 C4 接管时已存在，因此不能把该现象断言为三笔 Intensity 提交独有的回归。范围失控教训仍然成立；事故等级不替代因果证据。

永久要求：先追踪 Step0/既有实现，说明可以复用的机制；局部需求不得自动扩大到 Viewer、scheduler、provider、cache、prefetch、线程或算子。真实视觉、加载顺序和交互响应必须进入已批准的验收标准，最终像素正确不足以证明体验正确。

## 事故二：Step5 复核擅自扩大威胁模型

以下为用户提供的事故事实，未在本仓库复核 Step5 源码：F1-C 本应保存问题卡规划进度和待确认候选。复核却将私有函数调用、私有 ledger/current 篡改、object.__setattr__、pickle/clone、monkeypatch 和任意执行点异常注入升级成 blocker，推动多套 registry、authority、weakref、capability、事务 journal。内部防御复杂度超过原产品需求。

禁止重复以下循环：内部攻击实验 → 自动 blocker → 未授权加固 → 更多内部状态 → 再次加固。

## 永久审批与复核规则

1. **任务块是封闭白名单。** 复核只能验证批准的产品契约与验收门，不自行增加需求、威胁模型、状态机或保护范围。
2. **复核不是授权。** 正常公开产品路径可复现，或违反明确批准的安全边界，才可列 blocker；其他发现列 advisory，等待裁定。即使是 blocker，修复超出块范围仍须先审批。
3. **不默认防御同进程敌对代码。** 私有函数调用、属性篡改、monkeypatch、object.__setattr__、hostile pickle/clone、module reload、任意指令点异常注入，均不自动成为产品需求。
4. **新增机制须明确授权。** registry、authority、token、capability、journal、cache、scheduler、状态机及跨模块修改，先说明必要性、修改范围、用户影响、风险和回退。不能用“安全”“性能”“复核要求”替代批准。
5. **真实路径优先。** 测试公开操作和真实体验。可用受控延迟/故障验证已批准的普通 I/O 失败、异步迟到、关闭与切片行为；不因为测试可篡改内部对象而加固产品。
6. **两轮不收敛即停。** 连续两轮未发现新的公开产品路径缺陷时，停止 hardening，检查范围，不继续增加防御层。
7. **复杂度失衡即暂停。** 验证框架、防御或状态机复杂度超过原功能时，由用户决定删减、回退或扩围。

合理 blocker：用户未确认候选就执行；Step1 最新数据集显示旧数据像素；真实 ROI 外被错误补原始；正常关闭后仍有资源工作。

Advisory 示例：直接调用私有函数并篡改 ledger 后可绕过流程；任意 monkeypatch 可以让内部对象状态不一致。除非用户明确授权该安全模型，否则不得借此扩围。

每次交付说明本块范围、实际改动、公开复现路径、验收结果和未决 advisory。发现必要扩围时先停止依赖该扩围的实施，提供具体方案供用户审批。不得要求先把越界实现写完再批准。
