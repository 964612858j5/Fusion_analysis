# TMA F3 返工方案（F3b）：多通道看图 + 自然贴合的核心轮廓（第三版：codex 三轮审核通过；V 部分已由 docs/region_qc_module_plan.md 取代，M 部分并入该方案）

来源：用户第一次验收意见（2026-10-18，记录在 `docs/tma_f3_decisions_log.md` 末尾）。其中第 2、5、6 条和第 3 条里的"卡死"已经直接修好；本方案处理需要批准的三条：
- 第 1 条：TMA 页面要像 Step1 一样看多通道，有通道面板，可以选通道；
- 第 3 条：轮廓要略大于组织；
- 第 4 条：轮廓要像分水岭那样自然贴合，不要正圆。

这推翻了两项旧裁定：总方案 F3"TMA 缩略图不接 Rust 看图引擎"，以及 §2"核心外形初值 = 外接框 + 圆形掩膜"。

## V. 看图：第三个常驻看图（照 Step3 的做法）
### V.1 现状（代码依据）
- Step3 有自己的第二个常驻看图：`_step3_whole_slide()`（`ui/main_window.py:1931-1954`）调用 `Step1WholeSlideMount(..., camera_reason="step3")`，装进 Step3 页面的 `viewer_layout()`；进入和离开由 `_step3_follow_step`（:1979-2018）负责打开、暂停、恢复。
- 不能把同一个看图在页面之间搬来搬去：搬动可能要重建 OpenGL、重新上传纹理，以前已经否决过（`docs/step1_presegmentation_redesign_plan.md:987`；`Step1CoreLayer.attach` 在实现后再接会报错，`ui/step1_core_layer.py:111`）。Step1 的看图又是按 ROI 裁剪、按 Step1 的显示范围来画的，对整片 TMA 本来也不对。
- 看图的数据：原始片子的金字塔，按通道过滤（`viewer/step1_source.py:244-358`）。没有校正决定时，每个通道都是原始数据；没有 ROI 时就是整片。看图只从 `window` 上读取几个属性（`ui/step1_viewer_binding.py:66-96`），按文档说明可以用一个属性相同的小对象代替。
- 通道面板是同一个部件，在各步之间移动（`dock.mount_into`，`_channels_host_for` 只认 Step 0–3，`main_window.py:5276-5293`）。

### V.2 做法
1. **TMA 自己的看图（第三个常驻实例）**：新类 `TmaWholeSlideMount(Step1WholeSlideMount)`，用一个小适配对象代替窗口传入：
   - `loader.filepath` = TMA 片子（Step0 已提交的那张）；
   - 校正决定为空、无 ROI、`step0_output` 为空；
   - `_display` 用主窗口的同一个。

   结果是**整片、全部原始通道，不需要先 Save**。
2. **画什么**：在子类里重写三处，让它们都读一个新的显示范围 `"tma"`：
   - 显示快照 `_gpu_display_snapshot`；
   - 判断"哪些通道参与合成"的 `_gpu_composes`（`ui/step1_viewer_mount.py:866`），否则只在 TMA 里勾选的通道调亮度不会更新；
   - CPU 回退路径 `_start_cpu_backend`（:469）。

   共用的看图代码不改。

   具体显示方式：所有勾选的通道按叠加方式显示，每个通道权重 1，颜色和亮度窗口用全程序共用的那一套，所以和 Step0、Step1 一致。不进入融合，也不改 Step1 的任何设置。
3. **通道面板**：TMA 页面左栏上半部是通道面板（与 Step3 相同：`channels_host()`；行的内容是勾选、色块、名称，加上 Step0/Step1 已有的 `Intensity…` 入口），下半部是现在的对应表、编号面板和核心表。`_channels_host_for`、`_DISPLAY_SCOPES`、`dock.set_step` 加上 TMA。为此 TMA 改用自己的步骤号（不再借用 Step4 的切换）：进入时暂停 Step1 和 Step3 的看图，离开时暂停 TMA 的看图，做法同 `_step3_follow_step`。
4. **叠加层（圈 / 轮廓、标签、线和选取带、点选序列、拖动点）**：GPU 画面盖在场景之上，所以加进场景的东西会被盖住。照 Step1 预分割拼图已有的 `MontageOverlay`（`ui/step1_presegmentation/montage_view.py:75-160`）做一个透明、不接收鼠标的 `TmaOverlay(QWidget)`，放在看图视口上面，用 level-0 → 屏幕的换算来画；视野一变就重画；看图重建后重新挂上。
5. **鼠标**：在 `view_box` 里加一个看不见、铺满整片的"工具接收"图元。
   - 左键单击交给现在的 `MapController`；
   - 左键拖动：工具认领就交给工具（`Line` 画线、`Circle` 画圈、拖动已选中的块），不认领就忽略，让看图照常平移，与 Step1 一致；
   - 滚轮：只有正在画编号线时才用来调选取带宽度，其余时候照常缩放（视口事件过滤器）；
   - 右键：接看图已有的 `sigRightClicked` 信号，弹出菜单。

   `MapController` 接收的已经是 level-0 坐标，接到新看图上不用改；但多边形块需要的改动见 M.3。
6. **视野**：TMA 用自己的视野，不和 Step0、Step1、Step3 共用；`Prev` / `Next`、点表格行都改用 `mount.show_patch(外框)`。"在 Step1 看大图"按钮因此可以去掉，因为 TMA 页面自己就能看大图（请用户确认）。
7. **原来的 DAPI 缩略图**（`ui/tma/core_map.py`）：保留，作为看图打不开（GPU 失败且回退也失败）时的后备显示，放在 `install` 的提示位置。它也要改成能画多边形轮廓（见 M.3），所以列入白名单。

### V.3 代价
- 多一个常驻看图：一个 Rust 看图实例、读图线程和缓存（原始数据缓存上限 512 MiB，GPU 原始纹理预算 1536 MiB，`core/resource_tiers.py:54-76`）。显存紧张时，隐藏的看图会把图层按需降到粗层（`ui/gpu_memory.py`），不是整个释放。和已经接受过的"两个常驻看图"一样，只是变成三个。
- 新的常驻看图属于需要明确授权的新机制（AGENTS 第 1、4、5 条），请用户批准。

### V.4 和 Odon 的对照
| 项目 | Odon | 我们 | 复用 / 原因 |
|---|---|---|---|
| 多通道显示 | 每通道颜色 + 窗口，GPU 合成 | 直接用我们已经按 Odon 改造过的 Step1 Rust 看图 | 复用（同一引擎） |
| 标注叠加 | 点图层在 GL 里画（`annotations/mod.rs`，GL 实现 `annotations/gl.rs:67`） | 透明 QWidget 叠加层（照 `MontageOverlay`） | 不放进 GL：可编辑的轮廓需要随时改，叠加层更简单；数量（约 150 个）也不大 |
| 形状编辑 | 选中、拖动、Delete、Esc、撤销（`app.rs:5121-5292`、`:12418-12685`） | 现有工具不变 | 已复用 |

## M. 轮廓：自然贴合、略大于组织
### M.1 原型（Slice1，仓库外一次性画图）
用找核心时得到的组织块直接取外轮廓，再向外扩约 3% 核心直径。轮廓明显比原来的等面积圆更贴合组织，并略大于组织。图在 scratchpad 的 `outline_proto_crop.png`（黄色为新轮廓，紫色为原来的圆）。原型同时暴露两个问题，方案里一并解决：
- 两个挨着的核心向外扩以后会互相碰到；
- 片子上的亮雾会把轮廓往外拉出一块。

### M.2 做法（改 F2 的 `core/tma/dearray.py`，需批准）
1. **每块的轮廓**：
   - 找核心时已经有每块的掩膜（含分水岭拆开的）。先向外扩 `margin_frac × 核心直径`，默认 0.03，在 1 mm 的核心上约 30 µm，作为"略大于组织"的余量，可以调。
   - **扩出去的部分按分水岭分给离它最近的块**。原来的组织块**一个像素也不削**：只在新扩出去的部分里，和别的块相邻处留 1 个检测层像素的缝（原图约 16 像素）。
   - 两块原来就紧挨着时（分水岭拆开的粘连核心）：轮廓都沿各自边界像素的中心走，所以在原图层上，两块之间自然隔开一个检测层像素的宽度，不需要再削。代价是这条拆分线两侧各让出半个检测层像素（约 8 个原图像素）。这条线本来就是人为拆开的，不是组织边缘。
   - 取外轮廓、简化（误差半个检测层像素，小于余量，所以轮廓仍包住原来的组织块），用 A3 的 `level_to_global` 换算成原图坐标。
   - **顶点取整到整数像素并裁剪到片子范围内**之后才存，外框按整数半开区间算，所以后面的几何和锁定沿用现有规则（`RoiMask` 的语义不变）。
   - **"不交叠、包住原组织"按最终结果检查**：测试在原图层用与 `RoiMask` 相同的填充方法，核对相邻块之间没有共享像素、每块都包住它原来的组织块。留缝就是为了吸收取整和简化带来的误差。
2. **碎块不丢**：现在小于 10% 核心面积的块会被直接丢掉，Tonsil 的小碎块就是这样丢的。改成：扩边**之前**面积不小于 1% 核心面积的块都保留；更小的仍当灰尘丢掉。保留下来的块，初始分类沿用现有规则：不小于半个核心面积的先当核心，更小的先当碎块（未归属），由用户决定并入哪里。
3. **格式兼容**：
   - 候选列表升到第 2 版，每个候选多一个 `outline` 字段（原图整数坐标的多边形）；`load_candidates`（`dearray.py:288`）改为同时接受第 1 版和第 2 版。
   - 旧的第 1 版候选、旧草稿和旧锁定版本里的块没有轮廓，一律按圆处理，所以已有的结果都不会失效。
4. **亮雾**：现在靠纹理已经能挡住大部分平滑的光晕。被拉出去的少数情况，在页面上用编辑工具修（见 M.3）。

### M.3 页面上的轮廓编辑（`core/tma/layout*.py`、`ui/tma/`）
- 每块的外形改为：多边形（来自找核心的结果），或圆（用 `Circle` 画的，以及旧数据）。`MapController` 要随之改：
  - 点选改为"点在多边形内"（圆仍按圆）；
  - 移动改为平移全部顶点；
  - 改大小改为以块中心等比缩放顶点；
  - 新增顶点拖动；
  - 叠加层和后备缩略图都按多边形画。

  区域外形的规则不变：一块直接用它的多边形；多块先在原图分辨率下合并，再连成一条轮廓。`region_id` 的生成规则也不变。
- **移动**：整块平移。**改大小**：拖 8 个拖动点，按块的中心等比缩放，形状不变。
- **改形状**（新增，请用户决定是否本次就做）：
  - 甲：顶点拖动——选中一块后显示它的顶点，拖动单个顶点；
  - 乙：画笔加 / 擦——9 月规范里有，原定后续再做。

  建议本次先做甲；乙仍放后续。
- 锁定检查（不同核心的区域不重叠、外形不能退化）和版本规则都不变。

## 测试与验收
- **自动**：
  - 合成片上轮廓贴合（扩边以后包住整块，相邻块不交叠）：
    - 两块紧挨（分水岭拆开）时，两块都基本保住（只让出拆分线两侧各半个检测层像素），且不交叠；
    - 块贴着片子边缘时，不被削掉；
  - 第 1 版候选列表按圆兼容；
  - 碎块保留；
  - 多边形块的移动、缩放、顶点编辑和撤销；
  - 叠加层的坐标与看图视野一致；
  - 左键拖动平移、工具认领时不平移；
  - 进入和离开 TMA 时，三个看图各自的暂停 / 恢复；
  - 关闭程序时关掉 TMA 的看图，放在现有"可以拒绝关闭"的检查之后；
  - 第 1 版候选、旧草稿、旧锁定版本按圆读入。
- **全量回归**。
- **真机**（用户）：
  - Step0 载入片子以后，**不点 Save、不进 Step1**，直接进 TMA：能看多通道、选通道、调亮度（TMA 里单独勾选的通道也能调）；
  - 换片子以后 TMA 看图正确重建；
  - GPU 失败时：CPU 回退仍能显示所选通道和亮度；两种都失败时，显示 DAPI 后备缩略图，轮廓和编辑照常可用（自动测试用受控的失败来模拟）；
  - 三个看图同时存在时的内存和切换速度；
  - 轮廓贴合且略大于组织，相邻核心不交叠；
  - 左键平移；
  - 然后接着做上次没做完的验收第 4–8 步。
